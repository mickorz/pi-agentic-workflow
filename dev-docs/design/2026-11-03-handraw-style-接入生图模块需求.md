## 1. 它是什么

编号化的风格/排版/配色提示词库，配套 Skill（面向 Codex 形态）与离线画廊：

| 资源 | 规模 | 说明 |
|---|---|---|
| STYLES.md | 365 种（FA~FI 分类 / 001–368 传统编号） | 手绘与写实视觉风格，每个编号带中英双语核心风格特征提示词 |
| LAYOUTS.md | 170 种排版图型 | 社媒卡 24 / 信息图 38 / 漫画分镜 71 / IP 设计 13 / 电商 24 |
| COLORS.md | 36 种经典单色（C-01~C-36） | 克莱因蓝、柿子橙等，一键统领画面色调 |
| model_capabilities.json | 模型适配矩阵 | 显式标定模型（gpt-image-2 首发）按"作者名+风格名→正向特征→参考图兜底"优先级激活；通用模型自动 4-grid 参考图兜底 |
| gallery/*.html | 离线交互画廊 | index/layouts/colors 三页，本地浏览器检索放大、一键复制提示词 |

核心机制：**选编号（风格 × 图型 × 主题色）→ 输出实测验证的中英双语提示词 → 复制到任意生图工具出图**。另有智能推荐（不指定编号自动匹配）、纯图/图文双模式、文章封面设计器（原生支持 2.35:1/21:9，与我们微信封面约定吻合）、长文配图规划与 Markdown 自动回填。

## 2. 为什么接入（与我们生图模块的关系）

现状：`dev-examples/wx-article/scripts/image_gen/` 的提示词面由 image-prompts.json 承载，风格层只有两个来源——账号统一 3D 风格头（style_prefix）和 diagram provider 的扁平编辑风。缺口：

1. **风格多样性**：正文题图/金句卡/封面想要账号 3D 风之外的画风时，只能手写描述，质量不稳定；handraw 编号化风格是实测验证的资产，可消除"每次生成都漂移"
2. **排版图型**：170 种图型直接覆盖公众号题图、信息长图、金句卡、漫画分镜场景
3. **模型适配经验**：我们 image-use web 后端走 ChatGPT 生图，其"显式标定→特征注入→参考图兜底"分层策略与 model_capabilities.json 的能力清单可直接复用/共建
4. **封面比例原生对齐**：其封面模式首选 2.35:1，与微信封面精确比例约定一致

## 3. 候选接入方式（待定案）

| 方案 | 内容 | 代价 |
|---|---|---|
| A 轻量提示词注入 | image-prompts.json 的 item 增加可选 `style_ref`（如 `FB-006` / `C-01`），generate/export-review 时把编号对应双语风格提示词注入 prompt 头，覆盖或叠加 style_prefix | 小；只 vendor 三份 md + capabilities json |
| B 完整 vendor | 拉整个仓库进 thirdparties/（含 gallery html 交互选图），本地画廊选编号 → 写回 prompts | 中；体积与更新维护 |
| C 运行时引用 | 不落仓库，用时按编号从上游 STYLES.md 拉取 | 依赖网络与上游稳定性，离线不可用 |

倾向：**A 起步**（与 diagram provider 的 source 注入模式同构），gallery 交互选图可后置。

## 4. 约束与开放问题

- **许可署名**：上游要求保留作者 yang0 与原仓库地址；接入时在 vendor 目录 README 或 NOTICE 落署名，生成图产出无署名义务
- **账号风格一致性**：账号系列封面目前统一 3D 风；handraw 编号应定位为"可选覆盖"而非替换默认，避免系列封面风格漂移（需与账号定位一起定案）
- **文字入画对齐**：其图文模式 vs 我们的关键词文字设计 + expected_text 验收（T4 契约）如何对齐；小字多、乱码风险需过视觉核对
- **新规范适配**：接入后的图必须过 G.5 排版审阅 + 手机竖屏 390px 可读性（有效字号 ≥10px）验证
- **风格资产更新**：上游 365→368 已有增量，vendor 需记录版本与更新方式
