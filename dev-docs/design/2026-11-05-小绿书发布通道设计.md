# 小绿书发布通道设计（贴图=newspic，2026-11-05）

> 术语定案（2026-11）：贴图=小绿书，发布贴图一律叫"发布小绿书"。
> 需求背景：原发布链路只支持文章（news + freepublish）；`wechat_sticker.js` 只产出到本地图片，
> 交付 checkpoint 写明"微信原生图片消息本套件未实现"。本设计补齐小绿书（newspic 图片帖）发布通道。

## 核心结论

微信小绿书（图片帖）**不需要单独接口**：同一个 `draft/add`，article 里带 `article_type: "newspic"`
即成图片帖草稿。参考实现：`thirdparties/wewrite/src/wewrite/toolkit/publisher.py` 的 `create_image_post()`。
（此前"草稿接口不接受 news 以外类型"的说法不成立，已纠正。）

## 方案要点

1. **API 层**（`draft_manager/wechat_draft_api.py`）：
   - `WechatClient.image_post_add(article)` / `MockWechatClient.image_post_add(article)`：newspic 草稿，
     inject 语义与 `draft_add` 完全一致（add-timeout / add-errcode / crash-after-add）；
   - 图片走永久素材（`material/add_material`，复用现有 `add_material_image`）；mock store 记
     `article_type` + `image_media_ids`；`draft_update` mock 同步支持 newspic 字段。
2. **执行器**（`draft_manager/publish.py` 新增 `--xiaolvshu` 模式）：
   - 输入：`article_dir/imgs/` 下图片（png/jpg/jpeg/gif，自然序，1~20 张，webp 不支持）；
     标题 > `--title` > article.yaml（>32 字截断）；配文 > `--content` > `--digest` > article.yaml
     digest（>1000 字按句读截断）；**无 cover/md/html**（首图即封面）；
   - Hash：`sticker-v1` 域（图片字节+标题+配文+appid），与文章 hash 域天然隔离；
   - 状态机/锁/失败语义与文章模式同构：同 Hash 复用（draft/get 远端核对）、变更 `draft_update`
     原地更新、pendingOperation 恢复（--resolve-media-id/--clear-pending）全部复用；
   - **kind 隔离**：state 记 `kind: sticker|article`，同目录混型发布显式拒绝（防互踩草稿）；
   - **freepublish 显式拒绝**：微信对 newspic 的公开发表接口未验证，`--xiaolvshu --freepublish`
     直接 [FAIL]，发表请到公众号后台手发（与 wewrite 行为一致）；
   - 输出契约：`[sticker] N images: ...` / `[2] IMG i/n OK media_id=...`；
     `[5] DRAFT OK` / `[6] state saved` / `=== ALL DONE draft_media_id=... ===` 与文章模式同字面量。
3. **工作流**（`dev-docs/planning/article-workflow接入/脚本/wechat_sticker.js`）：
   - 新增"发布小绿书"阶段：`publish_method`（缺省 `draft`=发布；`none`=只交付），
     无 article_dir/审图不过自动跳过；调 `publish.py --xiaolvshu`，契约文案与退出码语义同
     `article_publish.js` 执行器模式；返回值增加 `publish` 字段。
