## 二、根因模式（3/3 样例一致，非个案）

### 模式 1：零文字负向约束系统性失效（日报卡点 2 的实锤与深化）

style_prefix 明确写入："画面中不出现任何文字、字母和数字，信息卡片上只放抽象图形与图标"。
三张图全部大量出现文字，且**文字内容与 prompt 语义精确相关**（"前端开发/后端开发/联调测试"对应拆墙叙事、"Infra 工程师"书脊对应双工程师叙事）——这不是乱码噪声，是模型**主动把抽象卡片具体化为带标签的信息图**。

结论：在 image-use web 后端（ChatGPT gpt-image）上，**中文长 prompt 中的负向文字约束基本无效**，且模型有强烈的"信息图加字"先验。

### 模式 2：构图叙事被"信息图模板"劫持（日报卡点 1 的执行层成分）

模型稳定输出"顶部标题横幅 + 左右双面板 + 标签连线"的标准科普信息图结构，忽略 prompt 中的空间叙事要求（拆墙缺口/青绿光晕/穿行递卡/地面箭头等要素 3/3 缺失）。风格层（机器人形象/主色系/3D 质感/宽高比）遵循良好——**正向风格描述有效，空间叙事与负向约束无效**。

### 模式 3（附带发现）：manifest 与文件系统证据链断裂

`--verify-only` 结果：manifest 记录的 5 个 path **全部 missing**。imgs/ 实际文件为中文文件名（`01-AI打破前后端边界.png` 等），与 manifest 记录（`ai-breaks-the-wall.png` 等）完全脱钩——下游发布管线重命名/替换后未同步 manifest，导致"哪张图对应哪条 prompt"已不可精确追溯（本报告的样例-条目对应是按风格与主题推断的）。

这是 T3（证据链补强）的现实需求实证：manifest 必须跟随文件名变更，或下游重命名前先解除 manifest 绑定。

## 三、改进指向（回填对应方案）

1. **文字问题 → 《本执行方案》T4 修正依据**：
   - "零字图"目标在 web 后端不可达。文字策略二选一：
     (a) **接受"有字但须正确"**：`expected_text` 契约从"验证无字"翻转为"验证指定字"——要求出现的文字显式声明，content_review 人工审核对照；
     (b) **无字底图 + 确定性叠字**：封面主标题后期合成**已是现网实际实践**（样例 3 的主标题即后期叠加，字体干净、非生成），路线可行性已获实证。
   - 封面需求矛盾显式化：公众号封面通常需要主标题，但要求"AI 生成图内零文字"——两者应拆开：底图零字（尽量）+ 标题排版层确定性叠加。
2. **构图问题 → 《生图流程优化执行方案》（V2.1）编译层**：
   - 空间叙事结构应作为 prompt 最高优先级前置（第一句锁定布局骨架），并考虑对"顶部标题横幅/分栏标签"倾向加显式负向约束（措辞待 A/B 验证，中文负向约束有效性存疑，可测试英文 `no title banner, no labels, single continuous scene`）。
   - 该问题属提示词设计层，不在本执行方案范围，回填至该方案 issue 清单。
3. **证据链断裂 → 本执行方案 T3**：
   - 下游重命名与 manifest 解绑问题需在 T3 一并处理（重命名同步或显式解绑语义），否则 content_review 的 image_sha256 绑定同样会被重命名破坏。
4. **样例量边界（按方案 V2 明确）**：3 张样本足以确认模式（3/3 一致），**不足以统计文字违规率**；T4 优先级依据是"模式确凿"而非"普遍率"。
