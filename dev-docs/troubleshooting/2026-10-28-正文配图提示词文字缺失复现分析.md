# 正文配图提示词"文字缺失"复现分析（2026-10-28）

## 问题现象

《Personal Agent 元年：蚂蚁灵光 2.0》文章配图提示词编写中：

- 封面条目按用户新要求补了关键词文字（「灵光 2.0」+ expected_text 验收）后；
- 新增的 3 张正文图（01 分水岭 / 02 蚂蚁家底 / 05 站在 App 之上）提示词**全部没有设计任何文字**，也没有声明 expected_text——被用户指出"老问题又出现了"。

"老问题"指：T0 取证阶段（`2026-10-28-T0生图质量全链路取证报告.md`）曾围绕"零字约束/文字缺失"排查过一轮，策略已翻转为"验证指定字"（T4 expected_text 闭环），但本次正文图提示词仍产出无字设计。

## 排查过程

1. **账号级 visual 规则**（`dev-examples/wx-article/visual/visual-rules.md`）：
   - 第 55 行："如画面包含文字，仅限一个短词或短语，字号大、笔画清晰，不排长句。"
   - 结论：账号规则**允许**短词短语文字，并不是零字约束。零字条款不来自这里。
2. **旧文章的 style_prefix**（《未来的软件公司》compile 产物）：
   - 尾部带"画面中不出现任何文字、字母和数字，信息卡片上只放抽象图形与图标"——这是当时 types/series 层或手工注入的禁字条款（T0 报告已把"系统性零字约束"叙事作废/降级为待重取证据）。
3. **本次手写 prompts 的过程**：
   - style_prefix 从旧文章复制，改封面时删除禁字、加封面文字，但**"正文图默认无字"的旧惯例没有翻转**——3 张正文图照抄"卡片只放抽象图形"的构图惯性，未设计章节关键词文字。
4. **校验层**（`image_gen/lib/validate.mjs` 第 95-99 行）：
   - expected_text 是**可选**字段："若提供必须是非空字符串数组"——只校验格式，不提示缺失。
   - 全链无"关键图（封面/章节主图）应带关键词文字"的门或 lint，漏设计无人拦截。

## 根因

三层叠加：

1. **惯例沿袭**：旧模板禁字条款虽已在封面条目修正，但"正文图无字"的默认设计惯性仍在，手写 prompts 时未逐条对齐新策略（关键图带短词短语）。
2. **规则与实现脱节**：visual-rules.md 允许短词文字，但 types/series 模板与手写流程没有一个"关键图默认带关键词"的正面约定；正反两个方向都靠人记。
3. **无校验门**：expected_text 可选 + 无缺失提示 → 策略翻转后没有机制保证落地，复现是必然而非偶然。

## 解决方案（本次）

3 张正文图按 visual-rules"短词、大字、清晰"纪律补齐关键词文字与 expected_text 验收：

| 图 | 新增文字设计 | expected_text |
|---|---|---|
| 01 分水岭 | 左灰暗区大标签「问完即忘」，右明亮区大标签「一直盯着」 | ["问完即忘","一直盯着"] |
| 02 蚂蚁家底 | 三枚徽章分别写「记得住」「盯得住」「办得了」（九字真言上图） | ["记得住","盯得住","办得了"] |
| 05 站在 App 之上 | 顶部大字标题「站在所有 App 之上」 | ["站在所有 App 之上"] |

同时 image-prompts.json 的 style_prefix 已改为"文字只允许出现在指定标题位置"，封面与正文口径统一。

## 预防 / 后续建议（待办）

1. **visual 规则补正面约定**：visual-rules.md 或 types/cover.md 明确"封面必须带主标题关键词；章节主图建议带一个短词短语"，把"允许"升级为"关键图默认要"。
2. **validate 加软门**：image-prompts.json 中 kind=cover 的条目若未声明 expected_text → WARN（不阻断，但渲染进 export-review 文档头部提醒审批人）。
3. **export-review 呈现**：审批文档逐张明细已回显 expected_text；可再加一行"未声明文字要求"的高亮，让审批人一眼看出漏配。
4. 手写 prompts 时（agent 或人工）以本文档为检查项：**每张图先问"这张图的关键词是什么"**，再写构图。
