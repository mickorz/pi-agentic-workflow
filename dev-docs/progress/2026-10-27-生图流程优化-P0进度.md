## 关键验证结论（对应方案验收项）

- 内容不变重编译 → `changed=- added=-` 无误失效（C1）
- 改一条 heading → 仅该条 changed，其他条目 effective hash 不变（C2，未付费图继续复用）
- 改信息图规则 → 仅 ig 条目失效，rules_hash 仅 infographic 桶变化（C3 分桶精确失效）
- RAG 中段插入 → 既有条目身份全部保留，新增新建不误绑（D1，含新建抢占继承 id 的 bug 修复回归）
- 多候选歧义 → exit 3 冲突报告不自动继承（D2）；resolve-new 强制新建（D3）
- meta 残缺/篡改 → 拒绝复用重编译（C5/C6/E5）
- Compiler 产物被现有执行器 dry-run 接受（F1/F2）；batch 风格门在未审批时正确拦截（联通时观察到）

## 过程经验（坑）

- workflow DSL 不支持 ES import → 可复用逻辑放 `image_gen/lib/*.mjs`（Node 例外区）+ CLI，DSL 经 command() 调用。
- 稳定 ID 单遍分配有「新建抢占继承 id」缺陷（RAG 抢走 ig-02 迫使 MCP 改号）→ 改两阶段：先登记全部继承身份，再分配新建。
- promptBlock 只认 `## prompt-block` 段：测试追加规则内容到文件尾（checklist 段）不会触发 prompt 变化，rules_hash 却会变——测试必须在正确段落内修改。
- bash heredoc 传多行 JS 代码存在转义损坏风险（`\n` 变真实换行），改用行级 node 脚本修复；后续写文件型注入用 Python pathlib 或 node -e 行级操作。
