# 生图提示词风格头与 body 示意图风格冲突，ChatGPT 反问澄清导致不出图或风格跑偏

- 日期：2026-11-12（前缀缓存审计篇首例）
- 影响：gzh-article-craft F 阶段生图

## 问题现象

1. batch 生图 5 张中 1 张（01-时间戳打断）完全跑偏：竖版扁平示意图被画成黑铬科技海报（横版 3D 渲染）。
2. 单独 regenerate 该图时，ChatGPT 不出图，回复澄清问题："你提供的两段视觉风格存在冲突……你希望采用哪一种？"随后 325s 超时（E_TIMEOUT，扣费不确定）。

## 排查过程

- 打开 E_TIMEOUT 返回的会话 URL，看到 ChatGPT 原话——它在等用户二选一，图永远不会出。
- 对照发出去的 prompt：`style_prefix（黑铬海报） + "\n---\n" + body prompt（扁平编辑示意图）`，两段风格硬冲突。
- 批量时 02/03/05 三张侥幸通过（模型自己选了 B 段），01 被随机站队成海报——同根因的两种症状。

## 根因

`generate.mjs` 的 `enrichPlan()` 把 style_prefix 无差别拼接到所有 item（含 body 示意图）前面。风格头是为封面设计的，body 竖版示意图自带完整风格描述，两段并存即冲突；ChatGPT 收到冲突指令时的行为不确定（反问 / 随机选一段），导致跑偏或挂起。

## 解决方案

`enrichPlan()` 修改（commit 见同日 feat）：非 cover 条目在风格头与 prompt 之间插入固定消歧指令——
"注意：若上方风格段与下方风格描述冲突，以下方风格描述为准直接出图，不要询问澄清。"
- fullPrompt 只是发送文本；哈希口径 `promptHash(style_prefix, prompt)` 按两字段分别计算，不受影响，风格审批绑定不失效。
- 另附手机可读性教训：01 重生成时把"左右两栏"改为"上下两栏、文字尽量大、不出现英文代码注记行"，390px 宽验证从半数标签失读变为全项通过。

## 预防/注意事项

- 已由 enrichPlan 修复，后续篇不需要在 prompt 里手写消歧句。
- E_TIMEOUT（提示词已提交未确认出图）先开会话 URL 看 ChatGPT 是否在等澄清/等出图，再决定 recover 还是改 prompt 重生成——不要盲目重试。
- body 图若再遇风格跑偏，先检查 fullPrompt 拼装而非怀疑模型。
