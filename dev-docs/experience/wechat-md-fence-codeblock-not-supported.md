# 微信不支持 markdown 代码块：``` 围栏裸渲染且不可复制，用 :::prompt 容器

> 日期：2026-10-29
> 场景：Q版角色卡一文第 6 章正文放通用提示词，用 ``` 围栏成块，发布后格式乱、读者无法快速复制

## 问题现象

正文 ``` 围栏代码块经 publish 发布后格式错乱：围栏标记 ``` 本身渲染进正文，块内每行掉进兜底分支变成独立裸段落，读者无法整块复制提示词。

## 根因

`publish_html.py` 的 `convert_md` 只有标题/列表/表格/图片/引用分支，**没有 fence（```）分支**——围栏行与块内行全部落入兜底 `<p>` 渲染。微信编辑器本身也不支持 `<pre>/<code>` 的复制交互，即使转出来也没用。

## 解决方案

1. **正文写法**：需要成块展示、读者要复制的提示词/配置，直接用发布器已有的 `:::prompt ... :::` 容器（灰底绿边 section，微信渲染友好，行=段落，长按可复制）。
2. **根修（防复发）**：`publish_html.py` 新增 `_normalize_fence_blocks`，convert_md 入口先于 blockquote 归一执行——``` 围栏块自动转为 :::prompt 容器（跳过围栏行、块内非空行逐行成段、内容不剥字符），以后正文再写 fence 也不会裸奔。
3. 验证：fence 泄漏/`<pre><code>` 泄漏断言 + 容器计数 + 提示词各区块完整性检查全过；重发布成功。

## 预防 / 注意事项

1. 正文需要"读者复制"的内容，**一律 `:::prompt`，不写 ```**（fence 兜底只是保险，不保证样式意图）。
2. 容器内空行会被吞（行=段落），多行内容压成结构行（如【区块】合并单行）。
3. 已发布草稿改文重发：draft_update 必报 40007（见 2026-10-29-wechat-draft-update-40007 类似经验/commit 641916c），脚本自愈重置后**重跑即新建**，发完记得手动删旧草稿。
