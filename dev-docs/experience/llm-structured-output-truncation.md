# LLM 结构化输出超长被截断导致 schema 校验失败

## 问题现象

workflow 里 `agent(prompt, { schema })` 要求返回大 JSON（analysis 七段全文 + evidence 数条），
运行报：

```
agent "GitHub 项目分析" 结构化输出解析失败：模型回复不是合法 JSON
（回复前 200 字符：{"analysis_md":"## 一句话定位\n\nRequests 是..."）
```

开头是合法 JSON，说明不是格式错误而是**回复被截断**（输出 token 上限）。
runtime 的 agent 重试也救不回来——每次都超长。

## 排查过程

1. 回复前 200 字符完全合法 → 排除模型不会写 JSON；
2. 输入 README 截到 2 万字符没问题，问题在**输出**：七段每段写满 + claims 长句，
   中文输出轻松超过默认模型输出上限；
3. glm-5.3-flash 长输出场景下更容易触顶。

## 根因

提示词只给了内容要求，没给**输出长度预算**；模型按内容自由发挥，输出超限被截断，
截断的 JSON 必然解析失败。

## 解决方案

提示词显式加输出预算（三处齐改）：

1. 每段长度约束：「每段 60~150 字精炼不注水」（替代「不少于 40 字」这类下限式要求）；
2. 条数上限：claims「6~8 条，claim 一句话」；
3. 总量硬约束：「输出必须一次性合法 JSON，总长度控制在 2500 字以内（含 JSON 转义），超长截断会被拒收」。

修后同 prompt 稳定通过（psf/requests 真实仓库 78s 一次成功）。

## 预防/注意事项

- 凡 agent + schema 要求「整包大 JSON」的 workflow，提示词必须带输出预算，
  「不少于 X 字」这类只设下限的写法在大输出场景是事故源；
- 需要 markdown 长文时优先拆两次 agent 调用（先内容后结构化元数据），
  或让确定性环节（脚本）承担拼装，LLM 只产最小必要字段；
- 截断特征：报错里「回复前 N 字符」开头合法 JSON、结尾缺失——见到即查输出上限，别去改 schema。
