# 封面副标 390px 不可读与视觉审核口径失准（2026-11-18 游戏上架平台篇）

## 问题现象

1. 封面重生成两轮后，「首发选哪个最稳」小号红标签在 390px 信息流宽度下仍不可读（视觉工具判"字号过小、对比度不足"）；第一版主标题也只是"勉强可读"。
2. 第二轮重生成（双行标题版）后，视觉审核先在整图上判"两行标题均不可读"，但同一张图用裁剪放大单独读取则逐字全对，像素测量也显示主标题字高足够——审核口径自相矛盾。

## 排查过程

- 用 PIL 按标题颜色（暖白 #F1EEE7 / 信号红 #F1261A）做 RGB 掩码统计文字色带高度：主标题字高 124px，换算 390px 显示宽约 25px，远超 ≥10px 可读线。
- 把 390px 缩放图的标题区裁剪放大 3 倍单独送视觉模型，逐字读取完全正确。
- 结论：图本身合格，失准的是"暗色整图上的整图级审核"——VLM 对暗底小字的整体印象偏严，且同图重问口径漂移。

## 根因

- **副标不可读**：2.35:1 画布在 390px 宽下高度只有约 166px，任何"小号标签"形态的文案物理上不可能达到可读字号；这不是生成质量问题，是设计形态问题，重生成多少轮都治不了。
- **审核失准**：VLM 对"暗色整图+小字"的整图级判断不稳定，不能单独作为 390px 可读性的裁决依据。

## 解决方案

1. 封面提示词把关键副标**升格为标题级双行排版**（第二行红色、字号约为第一行的 3/5），废弃"小号标签"形态；改一轮即过。
2. 390px 可读性裁决以**客观测量为准**：色带像素高度换算显示字高 + 裁剪标题区放大单独读取，两者一致才下结论；整图级 VLM 判断只作参考。
3. 配图视觉核对通道：zai MCP 工具未在会话暴露时，用 DashScope qwen3-vl-plus 直调（`.pi/skills/gzh-article-craft/scripts/analyze_image.py`，读 DASHSCOPE_API_KEY，支持 --expected-text 逐项核对）；先例是 xiaolvshu-review-vision/review_pages.py 同一通道。

## 预防/注意事项

- 封面提示词避免用"小号标签/角标"承载关键文案；关键文案一律进标题字号体系。
- 390 验证出现"审核说不可读但比例/字高存疑"时，先跑像素测量再信审核结论，别盲目重生成烧额度。
- 重生成后比例可能漂移（如 1900x828=2.295），发布前 publish.py 的 ensure_cover_235 只认 ±1%，明显偏离需人工干预。
