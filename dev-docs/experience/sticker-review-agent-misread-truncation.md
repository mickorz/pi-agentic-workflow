# 小绿书审图 agent 误读"缺字截断"——疑似截断必须亲核后再判

## 问题现象

2026-11-10 mcode-stack 小绿书 7 卡审图，工作流内置审图 agent 判 5/7 页 REVISION_REQUIRED，理由集中在"文字缺字/疑似溢出截断"：页2"emphasis 缺'合集'"、页5"标题行尾'地'未读出"、页7"金句末行只读到'工程习'"。

## 排查过程

主 agent 用 zai 视觉工具逐张开图逐字转录核验：四处声称的"缺字"**全部不存在**——"合集"完整可见、"地"独立成行完整、"惯。"完整收句。审图 agent 的"缺字"是它自身读图（OCR）的假阴性，不是渲染缺陷。

## 根因

审图 agent 对大字号卡片图做逐字转录时，长行折行、孤字尾行、中西混排都容易读漏，它把"我没读出来"当成了"图上没有"，直接给出 REVISION_REQUIRED。5 判 4 误，误报率极高。

## 解决方案

- 审图意见中的"疑似截断/缺字"一律不直接采信：主 agent 用视觉工具亲核对应 PNG（逐字转录 + 显式问"末字是否完整可见"），核验通过即推翻该条意见
- 亲核通过后用 `mark_review.py` 以结构化方式落 APPROVED（审图人如实标注核验方式），`verify_cards --require-approved` 发布门不受影响
- 真实要修的两类问题仍然成立：注入器吞 `\n`（品牌名拆行，见 sticker-cover-title-newline-collapsed.md）与孤字尾行（改 pages.json 文案手工断行）

## 预防/注意事项

- 审图 agent 的 REVISION_REQUIRED 是"待核验线索"，不是终审结论；人工（主 agent）亲核才是终审
- 后续可把审图 prompt 收紧："疑似截断必须二次开图确认，OCR 假阴性不得单独作为 REVISION 依据"（已登记 AP-S1 遗留）
- 孤字尾行（末行只有 1-2 字）不算缺陷，但影响观感——规划阶段就按 h-display ~7 汉字/行、quote ~13 字/行的容量写文案并手工断行，省一轮返工
