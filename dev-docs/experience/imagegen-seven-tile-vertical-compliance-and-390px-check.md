# 七件套式竖版示意图生成遵从不稳与 390px 验证兜底（2026-11-19 Manus 张涛北大分享篇）

## 问题现象

image-prompts.json 里四张 body 示意图用同一款七件套式 prompt 模板（含"竖版构图（宽高比 3:4，宽度不超过 850 逻辑像素），纵向堆叠自上而下"），image-use（ChatGPT 订阅通道）batch 生成后 4 张里 3 张跑成横版（4:3 / 3:2 / 1.4:1），只有概念隐喻图（非条块清单）竖版成功。把"竖版长图，画面高度明显大于宽度，宽高比 3:4，禁止横向宽幅"提到 prompt 首句后重生成，仍 3 张里 2 张横版（仅 1 张救回）。

另外发现 AI 中文错字：初版一张图把「付费用户用钱投票」渲染成「付费用用户用钱投票」（多字，三个"用"）。

## 排查过程

- 对比前缀缓存审计篇（2026-11-12）同款 prompt 当时竖版成功——说明该遵从率本身就是概率性的，非 prompt 写法退化。
- 逐张用视觉分析工具核对：文字内容全部准确，问题集中在画幅方向。

## 根因

ChatGPT 生图对文本中比例描述的遵从权重低，画幅倾向由构图语义决定：横向条块/两栏对比的描述会强化宽画幅联想；"竖版"字样放句首也只能部分改善，属随机波动。

## 解决方案

不无限重试画幅，改以"手机可读性"为放行门：

1. **390px 实测兜底**：用 PIL 把每张图缩到 390px 宽（手机正文宽度），交视觉工具检查主文字/小字可读性。4:3 横版若主文字 ≥22px 等效、小字 ≥12px 等效即放行（公众号正文配图横版常见，问题场景是 2.5:1 以上的极端长条）；不达标才重排重生成。
2. **错字处置**：逐字核对 expected_text（视觉工具放大读原句）；发现错字先微调文案降低错字概率（如去掉「用用户」叠字改为「在用钱投票」），再删 image-manifest.json 对应条目强制 stale 重跑 batch——比原样重试命中率高。

## 预防/注意事项

- 写七件套式 prompt 时仍保留竖版措辞（提高竖版命中率的先验），但对结果预期是"约半数横版"，排期按需 1-2 轮重生成。
- 发布前"手机竖屏可读性验证"必须用真实缩放图（PIL resize 后）交给视觉工具，不要凭原图分辨率估算。
- 生成图中文错字是常态风险，凡声明画面文字的图一律逐字核对 expected_text 后才 --approve-text。
