## G-P2 抓出的两个 V1 预存 bug（已修）

1. **失败 run 谎报 run.cancelled 事件**（src/runtime/workflow-runtime.ts）：`executeWorkflow` 对任何根脚本异常置 `shared.aborted=true`（用于中止后续调度），runWorkflow 终态事件却拿它当「取消」证据 → 失败 run 发 run.cancelled 而 manifest=failed，事件流与终态自相矛盾。修复：仅 signal.aborted / WORKFLOW_ABORTED 发 run.cancelled；脚本异常（含人工拒绝）发 run.failed。
2. **checkpoint 拒绝后 manifest 被回翻 running**（src/application/run-service.ts wireCheckpointRecording）：Server 收 checkpoint.resolved 无条件 waiting→running 回翻，IPC 延迟下晚于 Worker 终态写入落地，把 failed 覆盖回 running → effective=interrupted（UI 显示已中断）。修复：approved:false 不回翻（拒绝即奔终态）。

## 设计决策

1. **fetch 而非 EventSource**：EventSource 不能带 Authorization 头，token 仅双头的安全约束决定。
2. **RunEventSync 框架无关**：状态机不依赖 React（deps 全注入），hook 只是薄包装——重连/补洞/done 逻辑可脱离 DOM 测试。
3. **vite dev 代理剥 Origin**：浏览器 Origin 是 vite 端口≠Server 端口，会被跨 Origin 全拒；代理层剥掉等价同源（仅 dev；生产同源部署无此问题）。代理目标经 PI_WORKFLOW_WEB_PROXY_TARGET 可配。
4. **幂等键 useMemo 保持重试复用**：网络错误时 Server 可能已受理，重试必须同键防重复创建。
5. **runModel 的 node.completed=ok 不看业务值**：节点状态由事件驱动，null/undefined 结果不误判失败。

## 踩坑

- Playwright 装完必须 `npx playwright install chromium` 匹配版本（cache 里旧版本对不上）。
- Playwright `text=确认批准` 会同时匹配按钮和说明段落（点在 `<p>` 上无效果）——按钮用 `button:has-text()`。
- SSE 长连接让 reload 的 networkidle 永不触发——用 domcontentloaded。
- option 元素在闭合 select 里对 Playwright 是 hidden——等待用 state:"attached"。
- vitest 假时钟下微任务热循环会饿死事件循环（sleep 必须真 setTimeout）。
- vite dev 只绑 localhost（curl 127.0.0.1 不通）；Server token 横幅格式是「token（本次会话）：」（旧 grep 匹配不到）。
- 冒烟脚本 meta.name 必须 snake_case；顶层 DSL（phase()/agent() 全局）是惯用法，default-export 解构写法在 fake runner 下 agent 未定义。
