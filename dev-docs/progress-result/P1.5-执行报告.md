## 4. 冲突点裁决（需求 9.4）

1. **超时语义**：已按需求落地（uncertain 类不重试、暂停转人工、unknown 态、显式解冻通道）。

## 5. 关键设计决策

- **绑定因子**：风格审批绑定 = style_prefix 哈希 + 预览条目提示词哈希 + 模型指纹 + 参考图哈希（sha256 复合）。其余条目 prompt 变更不失效风格审批（审批对象是画风而非构图，与需求「首张验证统一画风」语义一致）。
- **懒物化失效**：审批失效不主动回写，在 batch 门/approve-style/preview 失败三处校验时物化回 pending（无 watcher，零额外状态）。
- **两道门在微信链路的分工**：执行授权 = 网关 pendingAction 批准卡（facade 注入 skip_confirm，4ea12a7 一次授权契约）；风格确认 = workflow 内 checkpoint（不可被 skip_confirm 豁免，`style_approved=true` 仅供自动化/测试）。签字不能代替工牌，工牌也不能代替签字。
- **preview 单请求硬约束**：preview 模式强制 maxAttempts=1，可恢复错误也不重试（验收 1 字面语义优先于重试优化）。
- **分批语义**：`--max-images-per-run` 按「启动的条目数」前置切片（尝试也占预算），capped_remaining 报告，续跑复用同一审批（输入未变指纹不变）。
