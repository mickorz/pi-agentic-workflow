- **测试**：单元 91/91 pass；集成 4/4；真实故障注入 e2e PASS（SIGKILL → resume → `n1(replayed), n2(replayed), n3`，token 仅 n3 产生）。
- **验收**：P2-01…P2-07 全部通过（证据见正式报告）。

## 关键决策记录

1. **checkpoint 等待态红线**：无通道且无显式 `default` → CHECKPOINT_WAITING（退出码 3），绝不自动通过——覆盖参考实现的 `default ?? true` 行为（V1 执行文档 §4.4 明确要求）。
2. **副作用窗口策略**：resume 时交互确认或 `--yes`；非交互未决即拒绝——不承诺 exactly-once，但绝不静默重执行写类副作用。
3. **死进程补偿态**：`list` 对 status=running 且 pid 死的 run 显示 interrupted；不假设 running 记录仍有活动进程。

## 踩坑记录（值得沉淀）

- **CLI runId 未透传 bug**：`executeWorkflowRun` 未把 manifest.runId 传给 runWorkflow → 内部生成新 runId → journal key 与 manifest 目录内条目不匹配 → resume 全量重执行。修复：显式传 `runId: manifest.runId`。教训：**双身份源（manifest 与 runtime 内部生成）必须单源化**。
- node:test 的 `t.skip(condition, message)` 并非条件跳过——首参被当 message 处理，调用即跳过。正确姿势：`if (!cond) return t.skip(msg)`。
- kill -9 模拟 crash 要杀真实 node 进程（经 dist 直跑，避开 npx/tsx 包装层）。
