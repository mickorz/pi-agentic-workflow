## 4. 关键设计决策

1. **Server 预写 manifest，Worker 采纳**：supervisor.start 先写完整 manifest（pid=Server 占位+ownerInstanceId/startedAt），Worker ready 后覆盖真实 pid；engine.start 见已存在 manifest 只 updateManifest 不重建。resume 只补所有权字段不翻 status，防占位 pid 被 isPidAlive 校验拒绝。
2. **事件单写者**：Worker eventsToDisk=false 不落盘，事件经 IPC 全量转发给 Server，Server appendEvent 单写 events.jsonl+内存 buffer/waiters（哨兵 sequence<0 不转发）。
3. **handle 立即返回**：供 run-service.wireCheckpointRecording 早期订阅 checkpoint.requested（不能等终态 resolve）。
4. **白名单外不可见**：未知项目 NOT_FOUND（不区分不存在/未授权）；路径校验三层（形态→`..` 段→realpath 前缀）。
5. **幂等键**：内存缓存（进程内 FIFO 1000）+ Idempotency-Key 头/body 二选一；Server 重启后缓存失效属可接受（run 历史持久化仍在）。
6. **ajv removeAdditional:false**：覆盖 Fastify 默认静默剥离未知字段，additionalProperties:false 真正 400；保留 coerceTypes（数字/字符串宽松互转，可接受 ergonomics）。

## 5. 踩坑与经验

- Fastify 默认 ajv `removeAdditional:true` 静默剥未知字段（`{scriptPath:"/etc/passwd"}` 被剥后 202 而非 400）→ customOptions 显式关掉；coerceTypes 会把数字 projectId 强转字符串（保留，测试改用对象验类型错）。
- macOS `os.tmpdir` 在 /var symlink 下，路径断言必须 realpathSync 比较。
- 全量并发负载下 worker-supervisor 心跳 200ms/1.5s 太紧被误杀 → 非专测用例放宽 heartbeatTimeoutMs=10000。
- 后台 `( cd && cmd & echo $! )` 捕获的是 wrapper PID，node 本体存活 → stop 用 pkill -f 精确命令行兜底+等端口释放。
- examples/checkpoint-demo.js 尾部 check(fileExists) 在 fake runner 下必失败（fake 不写文件）→ 冒烟用例收敛为终态断言，用 examples/smoke.js 替代。

## 6. 遗留与风险

- 幂等键缓存为进程内存：Server 重启后同键会新建 run（PRD 未要求持久化幂等；P2 前端可带 runId 幂等回查兜底）。
- Worker 心跳超时缺省 30s：kill -9 后最长 30s+ 才标记 interrupted（可配置 heartbeatTimeoutMs；P2 UI 对 running 态显示 effectiveStatus 补偿）。
- E05（kill -9）在 G-P1 门未做真实 kill（单测已覆盖 worker-supervisor E05 用例）；门内以 cancel/resume/checkpoint 主链为主。
