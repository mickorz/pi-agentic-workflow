## 三、观察

1. **B 写作占一半（49%）**：主因是逐章确认节奏（7 轮对话），单章 agent 产出只要 1-2 分钟，其余是等待。这是刻意设计（防丢失、便于中途改），不是瓶颈缺陷；若用户信任可改"两章一批"压缩交互轮次。
2. **F3 humanizer 占 17%**：全文扫描+审批文档生成是纯 agent 耗时大头（约 20 分钟），主要花在长上下文逐章比对；批准后落盘只要 2 分钟。
3. **生成图环节只占 3%**：本篇正文图走原推截图（用户拍板），生成图只剩封面 1 张，relay 预检+preview+batch 一次通过，是历次最顺的一回。
4. **等待用户确认合计约 42%**：13 个交互点里，逐章 ok（7 次）和两次审批（prompt/humanizer）是大头。G.5 排版审阅用户只用了 6 分钟（切主题+导出+确认），说明免粘贴打开器有效降低了这步的摩擦。
5. **坑命中记录**：pitfalls #11（digest 抓成章题）命中并按规程手改；T4 文字验收因封面被挪 imgs/ 触发 path 断裂，更新 manifest path 后 approve 通过（sha 未变，符合"重命名断裂"容忍设计）。
