## 动机：两条线流程差异对照

| 维度 | 公众号文章线（gzh-article-craft） | 小绿书线（待拆出） |
|---|---|---|
| 产物模型 | 长文 md（3000-5000 字，逐章写作） | 成套 3:4 版式卡片（pages.json 页面规划，5~9 页，无长文） |
| 标题 | GEO 疑问句长标题（章题+主标题） | **≤20 字**钩子标题（2026-11-10 实测后台上限，见 xiaolvshu-title-limit-20.md） |
| 配图 | 引用截图 + AI 生图（image-prompts.json + 两阶段生图 + F2 入文） | 版式卡片渲染（html 组件注入）+ 截图证据页（contain 禁 cover）+ 可选 ai-image 页 |
| 审批门 | 章节确认 / humanizer 审批 / G.5 排版审阅 | 规划审批（页表）+ 审图（--require-approved 硬门）+ 发布授权（指纹绑定，不可 skip） |
| 发布通道 | draft/add（news）+ freepublish 发表 | draft/add（newspic）+ **后台手发**（freepublish 未验证，通道显式拒绝） |
| 文风纪律 | humanizer 去 AI 味全文扫描 | 卡片文案短句容量纪律（h-display ~7 汉字/行、quote ~13 字/行、手工断行防孤字尾行） |
| 质量验证 | 手机竖屏 390px 可读性验证 | 审图 agent 误读需 zai 亲核（sticker-review-agent-misread-truncation.md） |

结论：写作-发布管线几乎没有共享步骤，强行共用 skill 只会让两边流程互相污染（文章线的逐章制/GEO 章题/humanizer 对卡片线全是噪音）。

## 拆分方案要点（新 skill：`xiaolvshu-craft`）

1. **定位**：素材（README/笔记/截图/文章）→ 小绿书卡片组（封面+内容页）→ 审图 → 发布小绿书入草稿箱；调用 `sticker-cards` workflow 做确定性执行
2. **SKILL.md 骨架**（把散落规范收拢为正文）：
   - 页面规划规范：压缩阶梯/封面钩子（copy.title ≤20 字同步发布标题）/h-display 与 quote 字数容量/手工断行防孤字尾行/截图页 contain 禁 cover、20 字上限与指纹绑定（引用 xiaolvshu-title-limit-20.md）
   - 素材规则：截图尺寸预处理、ai-image 页谨慎使用（付费授权 checkpoint 不可 skip）
   - 审图纪律：审图 agent"疑似截断"必须 zai 亲核（引用 sticker-review-agent-misread-truncation.md），mark_review 结构化记录
   - 发布纪律：两阶段授权（prepare 指纹 → 人工批准 → execute 同指纹）、后台手发说明、断点续跑（resume 管道喂 y 引用 pi-workflow-non-tty-checkpoint-pipe.md）
3. **gzh-article-craft 侧**：清理/不动（当前无小绿书章节，只需在 G 入箱节加一行"小绿书走 xiaolvshu-craft，不走本 skill"防误路由）
4. **不动**：sticker-cards workflow、registry 注册、发布脚本（skill 是编排与规范层，执行层已就绪）
