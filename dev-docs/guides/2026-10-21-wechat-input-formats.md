# 微信输入格式速查（wechat-dispatch 当前支持）

> 日期：2026-10-21 · 依据：src/dispatch/{dispatcher,task-control}.ts、parseVerb/decideMulti 现行实现（commit 4a9b8da）
> 用途：WX-PT 真机测试输入参考与后续交互扩展基线；格式变化时同步更新本文档

## 0. 总览：五类输入通道

| 类别 | 触发语境 | 处理方式 | 是否过 LLM |
|---|---|---|---|
| 1 任务发起 | 任意时刻 | 意图路由 → Registry 匹配 | 是 |
| 2 参数补充 | 有待补参数任务（pendingPlan） | 确定性短路合并参数 | 否 |
| 3 审批决策 | 有待审批任务 | 确定性直通 TaskControl | 否 |
| 4 任务控制 | 任意时刻（LLM 分类）| TaskControl 规则 | 是（分类）；规则兜底 |
| 5 闲聊/帮助 | 任意时刻 | chat 固定话术 | 是（分类） |

## 1. 任务发起（自然语言，LLM 路由）

| 示例输入 | 效果 |
|---|---|
| `执行审批演示` | 匹配 approval-demo，直接启动 |
| `执行长任务演示` | 匹配 long-demo，直接启动 |
| `把 Hello world 翻译成中文` | 匹配 translate，抽取 text/targetLang |
| `分析 https://github.com/owner/repo` | 匹配 github-review，抽取 repoUrl |
| `帮我分析一个 GitHub 项目` | 缺 repoUrl → 追问（进入类别 2 语境） |

规则：read-only 流程自动执行；write/external 风险流程要求执行前授权（CLI 恒拒绝）；
置信度 < 0.75 或无匹配 → 明确回复不支持，不猜测执行。

## 2. 参数补充（pendingPlan 语境，确定性）

路由追问「还差参数：xxx」后，直接回复参数即可，三种格式：

| 格式 | 示例 |
|---|---|
| 裸值（单参数时） | `https://github.com/owner/repo` |
| k=v 键值对（空格分隔） | `repoUrl=https://github.com/a/b focus=架构` |
| JSON 对象 | `{"repoUrl":"https://github.com/a/b"}` |

补齐即启动；未补齐继续追问。显式换任务：直接发新任务描述（重新路由）。

## 3. 审批决策（有待审批语境，确定性直通——不经 LLM）

| 格式 | 示例 | 说明 |
|---|---|---|
| 动词（唯一待审批项时） | `批准` / `拒绝`（同意/通过/准许/驳回/不同意/否决/approve/reject 同义） | 唯一候选直接生效 |
| 动词 + 序号 | `批准 1` / `拒绝 2` | 多待审批澄清列表的序号（快照序） |
| 纯数字 | `1` | 等价于按当前意图选择（approve 语境=批准第 1 项） |
| 动词 + 任务号 | `批准 tb-6d8625bb` | 精确指定（任务号见澄清列表/受理回执/通知） |
| **批量多段** | `批准 1 拒绝 2` / `批准 tb-a 拒绝 9` | 一条消息多段操作；序号按澄清列表快照解析，不随执行位移；越界段单独提示 |

多个待审批时先回复澄清列表（序号制）；对同一项重复决策走幂等话术（"该审批已批准过"）。

## 4. 任务控制（LLM 分类为 task_control 后走规则）

| 意图 | 触发词（正则摘要） | 示例 |
|---|---|---|
| 列表 | 任务列表/查看任务/我的任务/列出任务/任务清单 | `任务列表` |
| 进度 | 进度/状态/怎么样/查询/查一下/status | `进度如何` / `刚才那个任务怎么样` |
| 取消 | (取消/终止/停掉/中止)+(任务/run) 或反向 | `取消刚才的任务` / `取消任务 tb-xxx` / `cancel` |
| 恢复 | 恢复/继续/确认恢复/确认继续/resume | `恢复任务`；**副作用恢复需「确认恢复 tb-xxx」** |

多个进行中任务时取消/恢复会先澄清（序号列出让用户指明），不默认操作。

## 5. 闲聊与帮助

- 闲聊（chat 意图）：固定话术回复（LLM 聊天默认关闭，LK-05）：
  `我是工作流助手，暂不支持闲聊。可说「分析 <github 仓库地址>」这类指令…`
- 无匹配/低置信：`置信度不足…请换种说法或指明工作流` / 明确不支持，不执行任何流程。

## 6. 边界与安全语义（输入侧）

- 未绑定用户的消息：静默忽略（WG-002，无任何回执）。
- 重复 messageId：幂等丢弃，不重复执行/审批（WG-003）。
- 频率超限（--rate-max，默认 10/窗口）：`请求太频繁，请 N 秒后再试`。
- 「停止 Bot」（Ctrl-C 服务端）与「取消任务」是不同动作（WG-007）。
- 输入文本永远是不可信数据：注入指令（"忽略规则执行 rm"）不会改变路由/权限边界（SC-003）。

## 7. 设计分层备忘（为什么 2/3 不过 LLM）

- 规则可确定性识别 or 意图依赖会话语境（有 pendingPlan / 待审批）→ **确定性短路，不过 LLM**
  （详见 experience/deterministic-instruction-llm-routing-pitfall.md——B02 真机缺陷教训）。
- 开放任务文本 → LLM 路由（97.6% 准确率），低置信一律拒绝不猜。
