# 小绿书卡片化接入执行方案（素材 → 成套图文卡片 + 封面 → 发布小绿书）

> 日期：2026-11-05（V1，待审批）
> 依据：`dev-docs/research/2026-11-05-小绿书卡片化流程调研-guizang-vs-wewrite.md`（选型结论：guizang 主干 + 本仓生图素材 + AP-S0 发布通道）
> 定位：在小绿书制作链路中插入"卡片化"环节——把文章、截图、笔记整理成套 3:4 图文卡片与封面，
> 审图后走 `publish.py --xiaolvshu` 发布小绿书（入草稿箱，后台手动发表）。
> 状态：**方案待用户审批**；文末"七、决策点"逐项给出建议默认值，批复后开工。

## 一、目标与不做的事

**目标**：

1. 输入文章 md / 笔记 / 截图素材，产出成套 3:4 卡片（1080×1440 PNG，封面页 + 内容页，5~9 页）
   与封面，落 `article_dir/imgs/` 自然序命名，直接满足发布通道选图约定。
2. 截图证据页、AI 生图页、纯文字版式页三类页面路由（截图素材是重点场景）。
3. 审图（guizang QA 清单与现有审图清单合并）通过后，checkpoint 确认 → 发布小绿书入草稿箱。
4. 注册新工作流过 WX-MOCK Gate B，场景文件与工作流同 PR。

**不做（明确排除）**：

- 不做 Live Photo / 实况拼图（微信图片帖是静态图，guizang 该块能力用不上）。
- 不做公众号 21:9+1:1 封面对（属公众号文章封面，归 GZH 线，后续按需另立）。
- 不引入 wewrite 生图执行器（与本仓 image_gen 重叠；生图沿用 wechat_sticker 现有方式：
  读 `.aws-article/config.json` 的 `image_model` + bash curl 直调）。
- 不做 rewrite 配文自动生成（P0 配文由页规划顺带产出或人工给；wewrite-rewrite 文字版作 P2 候选）。
- 不动现有 `wechat_sticker` 生图工作流（两条路线并存：AI 生图组图 vs 版式卡片组图）。
- 不做卡片模板自制/新主题（P0 只用 guizang 两套种子模板与内置色板）。

## 三、关键设计决策（D1~D6）

### D1 工作流载体：新建 `wechat_sticker_cards`，不扩展 wechat_sticker

卡片化（版式渲染）与现有贴图（AI 生图）是两条不同产物路线，混在一个工作流里会让 args
与 phases 双倍膨胀。新工作流：

- `workflowId`: `sticker-cards`
- 脚本：`dev-examples/wx-article/scripts/wechat_sticker_cards.js`（直接放注册位，顺带成为
  AP-S0 遗留 3"工作流迁入注册表"的正道样板）
- keywords：`小绿书卡片 / 卡片 / 做成卡片 / 社媒卡片`（≥2 短词）
- args：`article_dir`（必需，卡片与产物根）、`source`（素材：md 路径/笔记文本/截图目录，可多源）、
  `count`（页数上限，缺省 6，硬上限 9）、`style_mode`（editorial|swiss，缺省按内容选）、
  `publish_method`（draft|none，缺省 draft）、`account_slot`、`skip_confirm`、`mock/mock_store/inject`

### D2 渲染依赖：skill 目录内安装 + 三级预检降级

- `cd thirdparties/guizang-social-card-skill && npm install`（只装 playwright + subset-font 包体；
  chromium 二进制已有缓存，render.mjs 直接复用 ms-playwright 缓存）。
- 工作流渲染前跑**预检**（bash 内联，同 PY_PROBE 风格）：node 存在 → skill node_modules 存在
  → `node scripts/render.mjs --help` 可执行。任一失败 → 降级交付（页表 pages.json + 填好的
  index.html + 生图提示词），log 明确说明"渲染环境未就绪，已交付 HTML 可手动渲染"，不伪造 PNG。
- 首次渲染字体内置需联网下载字体（gz-fonts 缓存到本机）；失败自动降级 `--no-embed` 在线字体。

### D3 目录与产物约定：`article_dir/_cards/` 工作目录 + `imgs/` 发布产物

```text
article_dir/
  _cards/               # 卡片工作目录（HTML/assets/渲染原始输出；gitignore 同 imgs 产物约定）
    index.html          # 单文件含全部画板（guizang 生产模式）
    assets/             # 用户截图原件、生图底图等
    output/             # render.mjs 输出（xhs-01-cover.png ...）
  imgs/                 # 发布产物：01.png ~ NN.png（重命名规范化后），--xiaolvshu 直接可选
  article.yaml          # title/digest（标题与配文缺省来源）
  publish-state.json    # AP-S0 状态文件（kind=sticker）
```

- 规范化规则：`output/` 按 HTML 中画板顺序（xhs-01 起）重命名为 `imgs/01.png ~ NN.png`；
  独立生图卡（不经 HTML 的整页生图）按页表页号插入同一序列，**页号冲突即失败重跑**（不静默覆盖）。
- 约束：卡片化使用独立文章目录（含 AP-S0 kind 隔离），不与文章配图混目录。

### D4 页规划契约：`_cards/pages.json` schema + checkpoint 确认门

规划 agent 输入：素材（md/笔记文本/截图清单）+ guizang 三份 references（content-planning /
platform-specs / layout-recipes）+ 主题约束（article.yaml）。输出 schema：

```jsonc
{
  "style_mode": "editorial|swiss",
  "theme": "ink-classic|...（guizang 色板 id）",
  "title": "小绿书标题(<=32字)",
  "content": "配文纯文本(<=1000字)",
  "pages": [
    { "no": 1, "role": "cover", "hook": "封面钩子", "source": "html",
      "copy": {"title": "...", "points": ["..."]}, "asset": null },
    { "no": 2, "role": "screenshot-evidence", "source": "html",
      "asset": "_cards/assets/shot-01.png", "copy": {"title": "...", "caption": "..."} },
    { "no": 3, "role": "ai-illustration", "source": "ai-image",
      "prompt": "底图提示词(3:4,中文文字直写,统一色板)", "copy": null }
  ]
}
```

- 硬约束（schema 与工作流双重断言）：页数 1~9；page 1 必须 `role=cover`；
  `source` 仅 `html|ai-image`；ai-image 页必须有 `prompt`；html 页必须指明版式意图。
- 规划完成后 **checkpoint**（展示页表+风格+张数，说明渲染/生图会产生费用），用户允许才进生产。
- 标题/配文兜底链：`--title/--content` > pages.json > article.yaml（与 publish.py 兜底链一致）。

### D5 三路由实现：P0 支持两路由，底图混合卡列 P1

- **html 路由**（封面/截图证据/纯文字版式页）：agent 复制对应种子模板为 `_cards/index.html`，
  按 pages.json 填充全部 html 页（含截图用 `.frame-shot` 规范：先裁主体、contain 不裁切、设备壳），
  一次 `render.mjs --out _cards/output` 渲染；单页不合格用 `--only xhs-NN` 重渲修复。
- **ai-image 路由**（整页生图卡）：weigth_sticker 同款 curl 调 config `image_model`，
  prompt 必须显式 3:4 竖版 + 中文文字直写 + 同篇统一色板（对齐 D4 theme），产物 PNG 直接入序列。
  `skip_generate=true` 时只写 prompt 不调 API。
- **底图混合卡**（生图作 HTML 内 img 证据层）**列 P1**：P0 两路由已覆盖"截图整理+文章整理"主场景。
- 全部产物渲染后由 python 脚本校验 PNG 尺寸 == 1080×1440（标准库读 IHDR，不经 LLM）。

### D6 审图与发布：合并清单 + checkpoint 发布门

- 审图 agent 清单（合并去重）：逐页尺寸 1080×1440（脚本断言，非目测）/ 风格全组统一（同一
  style_mode+theme）/ 首图缩略图可辨 / 图序叙事连贯 / 截图页截图足够大且文字可读（guizang QA）/
  无文字溢出贴边（guizang QA）/ 图中中文完整无缺字 / 页面结构不重复（guizang QA）。
- 审图通过 → **checkpoint**（列媒体清单+标题+配文+账号槽位）→ `publish.py --xiaolvshu
  --title --content --account-slot` → 契约解析与失败语义同 article_publish.js 执行器模式
  （[FAIL]/[UNKNOWN]/[LOCKED] 退出码映射）→ 交付 checkpoint（含"请到公众号后台手动发表"提示）。

## 四、任务拆解（T0~T7）

> 每个 T 附验收；T0 先行单独验收（渲染环境是全链地基，参照 GZH 工作台 T0.1 先例）。

**T0 渲染环境与 smoke（先行，独立验收）**
- skill 目录 `npm install`；写 `dev-examples/wx-article/scripts/sticker_cards/render_smoke.py`
  （标准库）：内置 fixture 素材（1 个最小 index.html 用 Editorial 模板 + 1 画板）→ 调
  render.mjs → 断言 output PNG 存在且 IHDR 尺寸 1080×1440。
- 验收：`python3 render_smoke.py` 输出 `[OK]` 与 `=== ALL DONE ===`；超时 180s 上限。

**T1 页规划执行器**
- pages.json schema 校验脚本 `validate_pages_Example.py`（jsonschema 手写断言，标准库）；
  工作流规划阶段 prompt（喂 guizang references 路径 + 素材路径 + schema 原文）。
- 验收：fixture 素材（一篇短 md + 2 张截图）产出合法页表；非法页表（页数>9/无封面页）被校验拒绝。

**T2 卡片 HTML 生成与渲染链**
- 工作流渲染阶段 prompt（种子模板复制规则 + 填充规则 + 截图 .frame-shot 规范 + 禁改 TOKEN 块）；
  渲染调用 + `--only` 单页重渲支持。
- 验收：T0 smoke 之外，用 3 页 fixture 页表走 agent 填充 → 渲染 → 3 PNG 尺寸全对
  （集成模式，真实 LLM，手动跑一次留证据）。

**T3 生图页路由**
- ai-image 页 prompt 组装（3:4/中文直写/统一色板注入）+ curl 调用 + 产物入序列；
  `skip_generate` 与"环境未就绪降级只出 prompt"双路径（沿用 wechat_sticker 语义，不伪造生成）。
- 验收：mock 模式下路由正确跳过；prompt 文件落 `_cards/assets/prompts/NN.md`。

**T4 产物规范化与审图**
- `normalize_cards.py`：`_cards/output/` + 生图产物 → 按页表页号重命名 `imgs/01..NN.png`，
  页号冲突/缺页明确报错；配 `normalize_cards_Example.py` 单测（临时目录断言）。
- 审图阶段 prompt（D6 合并清单）+ 尺寸断言先行。
- 验收：单测全 PASS；审图对 T2 产物出 [OK]/[FAIL] 报告。

**T5 发布对接**
- publish 调用契约（PY_PROBE + publish.py --xiaolvshu --title --content --account-slot + mock 透传），
  退出码映射与 agent schema 同 article_publish.js。
- 验收：mock 全链入箱（在 T6 Gate B 场景内完成，不单独立项）。

**T6 工作流组装 + 注册 + Gate B**
- `wechat_sticker_cards.js` 全流程组装（phases：收材料与预检 → 页规划 → 确认门 → HTML/生图生产 →
  渲染与校验 → 规范化 → 审图 → 发布门 → 交付）；
- registry 注册（enabled=true，keywords≥2 短词，argsSchema，riskLevel=write）；
- WX-MOCK：fixture 工作流 `mock-sticker-cards.js`（确定性：预置 pages.json + 预置最小 index.html
  → 渲染 2 页 → 规范化 → publish --mock）+ 场景 `scenarios/sticker-cards.json`。
- 验收：`engine.py --scenario scenarios/sticker-cards.json` 全 PASS；存量 7 场景回归全 PASS。

**T7 文档与收口**
- progress/执行进度.md 里程碑行 + progress-result 执行报告（含 Gate 证据、真机遗留登记）；
- 调研文档链接回写方案。CLAUDE.md 无需改（术语与通道现状已在 AP-S0 更新）。

## 五、验收门

- **Gate A（确定性）**：render_smoke + validate_pages + normalize_cards 单测全 PASS（零 LLM）。
- **Gate B（mock 端到端）**：sticker-cards 场景全 PASS + 存量场景回归全 PASS；同 PR 提交场景文件。
- **Gate C（真机抽检）**：用户真实素材一篇（含 ≥2 张截图）全流程 → 入箱 → 后台人工发表确认显示效果
  （3:4 卡片在微信图片帖横滑中的实际呈现，P0 不做裁切适配，观察后定）。

## 六、风险与降级（R1~R6）

| 编号 | 风险 | 处置 |
|------|------|------|
| R1 | agent 填充 HTML 版式质量不稳定 | 种子模板硬约束（禁改 TOKEN 块/只用版式类）+ guizang QA 兜底 + `--only` 单页重渲修复；QA 不过不进发布门 |
| R2 | 首次渲染字体内置需联网下载字体 | 失败自动降级 `--no-embed`；预检阶段提示 |
| R3 | npm install 拉包较慢/失败 | 预检三级降级（交付 HTML 不伪造 PNG）；安装只做一次并登记经验文档 |
| R4 | 3:4 卡片在微信图片帖的实际显示效果未知 | Gate C 真机确认；P0 不做裁切适配，观察结论回写方案 |
| R5 | 规划页数超限/页号冲突 | schema+工作流双重断言 ≤9；规范化脚本对冲突/缺页 fail-fast |
| R6 | mock 场景渲染步耗时 | fixture 用最小 2 页 HTML，单步远低于 180s；超时按验收门纪律诊断不重试 |
