## 一、目标与不做的事

**目标**：

1. 输入文章 md / 笔记 / 截图素材，产出成套 3:4 卡片（1080×1440 PNG，封面页 + 内容页，5~9 页）
   与封面，落 `article_dir/imgs/` 自然序命名，直接满足发布通道选图约定。
2. 截图证据页、AI 生图页、纯文字版式页三类页面路由（截图素材是重点场景，带预处理环节）。
3. 两级审批：规划审批（页表/风格/数量）与发布审批（实际 PNG/标题/配文/账号）互相独立，
   发布审批不可被 `skip_confirm` 绕过。
4. 注册新工作流过 WX-MOCK Gate B，场景文件与工作流同 PR。

**不做（明确排除）**：

- 不做 Live Photo / 实况拼图（微信图片帖是静态图）。
- 不做公众号 21:9+1:1 封面对（归 GZH 线，后续按需另立）。
- 不引入 wewrite 生图执行器（生图沿用 config `image_model` + 确定性调用）。
- 不做 rewrite 配文自动生成（P0 配文由页规划 AI 生成 + 人工可改；rewrite 作 P2 候选）。
- 不动现有 `wechat_sticker` 生图工作流（两条路线并存）。
- 不做卡片模板自制/新主题（只用 guizang 两套种子模板与内置色板）。
- **不提前开发多平台发布适配器**（架构原则，见第五节）。

## 三、关键设计决策（D1~D9）

### D1 工作流载体：新建 `sticker-cards`（定案）

- `workflowId`: `sticker-cards`；脚本 `dev-examples/wx-article/scripts/wechat_sticker_cards.js`
- keywords：`小绿书卡片 / 卡片 / 做成卡片 / 社媒卡片`（≥2 短词）
- args（V1.1 补全）：

```jsonc
{
  "article_dir": "必需，卡片与产物根",
  "source": "素材：md 路径/笔记文本/截图目录，可多源",
  "count": "页数上限，缺省 6，硬上限 9",
  "style_mode": "editorial|swiss，缺省 editorial",
  "title": "小绿书标题(<=32字)，可选",
  "content": "配文纯文本(<=1000字)，可选",
  "publish_method": "draft|none，缺省 draft",
  "account_slot": "账号槽位，缺省 1",
  "skip_confirm": "仅跳过规划审批；发布审批不受其影响（P0-1）",
  "mock / mock_store / inject": "测试透传"
}
```

### D2 渲染依赖：submodule 内安装 + 三级预检降级（定案）

- T0 前置核对：`git submodule status` 确认 guizang 已初始化且 HEAD 与父仓库登记一致。
- `cd thirdparties/guizang-social-card-skill && npm install`（playwright + subset-font 包体；
  chromium 复用 ms-playwright 缓存，无浏览器大下载）。
- 工作流渲染前预检（bash 内联）：node 存在 → skill node_modules 存在 → render.mjs 可执行。
  任一失败 → 降级交付（pages.json + 提示词 + 说明），不伪造 PNG。
- 字体内置失败自动降级 `--no-embed`（smoke 与 mock 链路一律 `--no-embed`，离线确定性）。

### D3 目录与产物约定：`_cards/` 工作目录 + `imgs/` 发布产物

```text
article_dir/
  _cards/               # 卡片工作目录
    pages.json          # 唯一内容数据源（P0-2：Agent 只产这个文件）
    shots-report.json   # 截图预处理报告（P0-3：尺寸/告警/建议裁切）
    state.json          # 状态机当前态（P0-6）
    assets/             # 用户截图原件、生图产物（HTML 引用）
    prompts/            # 生图页提示词 NN.md
    index.html          # 注入器生成的渲染输入（确定性产物，非 Agent 手写）
    output/             # render.mjs 输出（按画板 id 命名）
  imgs/                 # 发布产物：01.png ~ NN.png（规范化重命名后）
  article.yaml          # title/digest（兜底来源）
  publish-state.json    # AP-S0 状态文件（kind=sticker）
```

- 规范化规则：`output/` 按页表页号 + 生图卡页号统一重命名 `imgs/01.png ~ NN.png`；
  页号冲突/缺页 fail-fast。
- 卡片化使用独立文章目录（AP-S0 kind 隔离），不与文章配图混目录。

### D4 页面数据契约：pages.json schema v2（P0-4）

```jsonc
{
  "version": 1,
  "style_mode": "editorial|swiss",
  "theme": "guizang 色板 id（editorial: ink-classic/indigo-porcelain/forest-ink/kraft-paper/dune/midnight-ink；swiss: ikb/lemon/lemon-green/safety-orange）",
  "title": "小绿书标题(<=32字)",
  "content": "配文纯文本(<=1000字)",
  "pages": [
    { "no": 1, "role": "cover", "source": "html",
      "layout": "cover-hook",                  // html 路由必填，枚举见注入器组件表
      "copy": { "title": "...", "points": ["..."] },
      "emphasis": "整页最重点的一句话或数字",   // 新增：版式放大主信息
      "notes": "特殊布局说明（如封面不放图）" },  // 新增
    { "no": 2, "role": "screenshot-evidence", "source": "html",
      "layout": "screenshot-with-caption",     // 必填
      "asset": "_cards/assets/shot-01.png",    // 必填（html+asset 类组件）
      "image_fit": "contain|cover",            // 新增，缺省 contain（UI 截图禁 cover）
      "crop": { "position": "center|top|bottom|<x% y%>" },  // P0-3：规划门人工确认后写入
      "copy": { "title": "实际运行效果", "caption": "..." },
      "emphasis": "...", "notes": "..." },
    { "no": 3, "role": "ai-illustration", "source": "ai-image",
      "prompt": "底图提示词(3:4 竖版,中文文字直写,统一色板)",
      "copy": null }
  ]
}
```

- 硬约束（schema 校验器 + 工作流双重断言）：页数 1~9；page 1 必须 `role=cover`；
  `source` 仅 `html|ai-image`；html 路由 `layout` 必填且必须命中注入器组件枚举
  （P0-4：不允许靠 Agent 理解意图，组件表外直接拒绝）；ai-image 页必须带 `prompt`；
  title ≤32 字、content ≤1000 字。
- 元数据兜底链（P0-5 统一定案，工作流与发布步共用）：

```text
title:   args.title   > pages.json.title   > article.yaml.title
content: args.content > pages.json.content > article.yaml.digest
```

- 校验器：`dev-examples/wx-article/scripts/sticker_cards/validate_pages.py`（标准库）+
  `validate_pages_Example.py` 单测。

### D5 版式组件表：注入器与 schema 共同绑定的枚举（P0-2 落地物）

P0 组件集（每个 = 注入器内一段固定 HTML 片段，只用种子模板已有 class）：

| layout id | 用途 | 必填字段 |
|-----------|------|----------|
| cover-hook | 封面钩子页 | copy.title、copy.points、emphasis |
| text-card | 单观点文字卡 | copy.title、copy.body |
| screenshot-with-caption | 截图证据卡 | asset、copy.title、copy.caption、image_fit |
| checklist | 清单页 | copy.title、copy.points(3~6) |
| quote | 金句/结论页 | emphasis、copy.caption |

- P0 只做这 5 个组件（覆盖封面/观点/截图/清单/结论主场景）；新组件 = 在注入器与组件表各加一段，
  页规划逻辑零改动（评审"未来加模板不需重设计规划"的落点）。
- 版式多样性由规划 agent 在组件枚举内组合（guizang"页面结构不重复"原则保留在审图清单）。

### D6 发布对接与两级审批（P0-1 / P0-5）

- **规划审批门**（受 `skip_confirm` 控制）：展示页表（页号/角色/layout/素材/钩子）+ 风格主题 +
  截图预处理报告 + 生图费用提示 → 允许 = 进入生产。
- **发布审批门**（独立，**不受 `skip_confirm` 影响**）：展示实际 PNG 清单 + 最终标题 + 最终配文 +
  账号槽位 → 允许 = 调 publish.py。与 article_publish.js 的独立授权设计同边界：
  制作确认 ≠ 外部副作用授权。
- 发布调用（P0-5）：**command() + 参数数组直传**，不经 shell 字符串拼接。实现与
  mock-sticker-publish fixture 同构：`command({ executable: "node", args: ["-e", RUNNER,
  publishPath, articleDir, title, content, slot, ...mock] })`，RUNNER 内 spawnSync 探测
  python3/python/py 后以 args 数组调 publish.py。路径与文本全部走 argv，无引号转义面。
- 发布退出码映射：0+PUBLISHED/DRAFTED 行 → DRAFTED；1 → FAILED；2 → UNKNOWN；3 → LOCKED。

### D7 渲染链：程序复制模板 + 确定性注入器（P0-2）

- Agent **只写 pages.json**（规划阶段唯一产物）；**Agent 零 HTML**。
- 注入器 `sticker_cards/build_html.py`（python 标准库，确定性）：
  1. 程序复制种子模板（submodule 内 `assets/template-<style_mode>-card.html`），
     `data-theme` 按 pages.json.theme 设置；
  2. 在固定注入点（模板画板容器区域）按 pages.json.pages 顺序生成画板：
     每页 = 组件表对应固定 HTML 片段 + pages.json 字段填充（文本走 HTML 转义）；
  3. 写出 `_cards/index.html`。
- CSS、画板尺寸、全局样式全部来自种子模板，Agent 与注入器均不修改；
  模板升级 = 换种子版本，组件片段按新 class 适配一次。
- 渲染：`command()` 调 `node scripts/render.mjs _cards --out _cards/output --no-embed`
  （单页修复用 `--only <id>`）；渲染后 `verify_render.py` 断言每页 PNG IHDR == 1080×1440。
- 离线确定性：smoke/mock 链路一律 `--no-embed`；生产链路先试内置、失败降级在线字体。

### D8 截图预处理（P0-3）

- `sticker_cards/prep_screenshots.py`（标准库）：扫描素材截图 → 逐张读 PNG/JPEG 尺寸
  （PNG 读 IHDR；JPEG 读 SOF 段）→ 输出 `shots-report.json`：
  - 每张：宽高、宽高比、判定（过小 <720px 宽 / 超长竖图 >1:3 / 比例与 3:4 画板差异）、
    建议处理（contain 全含 / cover 放大 / 建议人工裁切）；
  - 判"建议人工裁切"的截图在**规划审批门**逐张列出，用户确认或给出裁切指示，
    写入 pages.json 该页 `crop.position` 与 `notes`。
- P0 不做自动主体识别（列 P1：可接视觉 agent 或截图像素分析）；P0 用"程序检测 + 人工确认 +
  CSS 裁切（object-fit/object-position，在组件片段内实现，不动全局 CSS）"。
- 代码/GitHub 截图额外规则：contain 强制（禁 cover 裁切 UI）；宽度不足 720px 的截图在报告中标
  "文字可能不可读"，建议用户换高清图或放大局部后重截。

### D9 状态机：制作与发布分离（P0-6）

`_cards/state.json` 由工作流在各阶段边界经 command() 写入（`card_state.py` 标准库 helper）：

```text
PLANNING -> WAITING_PLAN_APPROVAL -> GENERATING -> RENDERED -> REVIEWING
        -> WAITING_PUBLISH_APPROVAL -> PUBLISHING
PUBLISHING 终态（映射 publish.py 退出码）：DRAFTED | FAILED | UNKNOWN | LOCKED
```

- 工作流最终 return 必须区分：`cards_status`（REVIEWED 及之前）与 `publish_status`
  （四终态之一或 none）。**UNKNOWN ≠ 成功**：图片已生成不掩盖发布结果不确定，
  return ok=false + 报告"按 [UNKNOWN] 提示人工核对草稿箱后 --resolve-media-id 恢复"。
- 状态与 publish-state.json（AP-S0）职责分离：前者管卡片制作流程，后者管微信草稿账号态。

## 四、架构原则：可复用内核 + 单一发布适配器（评审第五节采纳）

```text
内容输入层    md / 笔记 / 截图 / 图片（P0：文件与文本；文档解析 P2）
页面规划层    pages.json 契约（schema v2 + validate_pages）——可复用内核 1
卡片生产层    build_html 注入器 + render.mjs + verify_render ——可复用内核 2
             （AI 生图路由与截图预处理挂在这一层）
审核与产物层  审图清单 + normalize_cards + state.json
发布适配层    P0 仅 xiaolvshu（publish.py）；不做多平台适配器
```

原则：现在只沉淀"页面规划契约"与"渲染契约"两个内部抽象；公众号图文、其他平台图片组等
发布适配器等真实需求出现再按同一 pages.json 契约扩展，P0 零预建。

## 六、验收门

- **Gate A（确定性）**：validate_pages / build_html / prep_screenshots / normalize_cards /
  verify_render / render_smoke 全 PASS（零 LLM）。
- **Gate B（mock 端到端）**：sticker-cards 场景全 PASS（fixture：预置 pages.json → 注入 → 渲染 2 页
  → 规范化 → publish --mock，全确定性零 LLM）+ 存量 7 场景回归全 PASS；场景与工作流同 PR。
- **Gate C（真机抽检）**：真实素材一篇（含 ≥2 张截图）全流程 → 入箱 → 后台人工发表确认显示效果。
