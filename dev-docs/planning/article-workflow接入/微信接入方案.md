# article-workflow 微信接入方案

> 日期：2026-10-21 · 需求：《文章工作流接入需求.md》（目录→大纲 / 文章→发布）
> 现状核实：17 个脚本 DSL 原语与本项目完全兼容（meta/phase/agent/workflow/check/log/args），
> **全部通过确定性校验**（无 Date.now/Math.random），自包含。

## 一、需求与脚本映射

| 需求 | 对应脚本 | 状态 |
|---|---|---|
| 1. 传 Obsidian 目录 A → 分析 + 大纲 | `article_collect_images.js` 覆盖 1.1/1.2（扫描引用→下载 imgs→图片清单）；**大纲生成需新写**一个编排脚本 | 需新写 `obsidian_outline.js`（组合） |
| 2. 传文章 → 直接发布 | `wechat_md_to_draft.js`（md→HTML→上传→草稿箱，article_dir+cover+account） | 现成 |

## 二、风险定级与微信触发现状（关键约束）

Dispatcher 现状：`riskLevel != read-only && !authorized → NOT_AUTHORIZED`（§2.1-5 执行前授权），
微信端未传 authorized → **write/external 一律拒绝**。执行前授权协议（PendingAction）属 AM-P0 T4，未实现。

| 流程 | 定级 | 微信端现在能触发吗 |
|---|---|---|
| obsidian-outline（分析/下载图/清单/大纲，写限用户传入目录） | **read-only**（写范围严格限定 args 传入目录，模型不碰其他路径；与 wx-p2 approval-demo 定级惯例一致。AM-P0 后建议升 write 走授权） | ✅ 可自动执行 |
| wechat_md_to_draft（上传素材/建公众号草稿） | **external-side-effect** | ❌ NOT_AUTHORIZED（明确回复需授权，不是"找不到流程"）；发布走 CLI：`pi-workflow run wechat_md_to_draft.js --args '{"article_dir":"...","cover":"..."}'` |
| 发布/群发（publish_method=published） | external-side-effect | ❌ 同上，AM-P0 后经 PendingAction 授权放开 |

> 建议发布类也**注册进 Registry**（keywords/examples 完整）——微信触发得到"需授权"引导话术，
> Agent/路由可正确理解；而非误报不支持。

## 三、接入步骤

### S1 脚本落位

```text
dev-examples/wx-article/
  registry.json          # 本主题注册表（wechat start --registry 指向它）
  scripts/
    obsidian_outline.js          # 新写（见 S3）
    wechat_md_to_draft.js        # 自 脚本/ 复制
    article_collect_images.js    # 子流程依赖，复制
    references/                  # skill 参考文档（agent prompt 引用），自 脚本/references/ 复制
    config/README.md             # .aws-article/config.json 与 aws.env 准备说明（凭证不入库）
```

### S2 兼容性微调（复制后）

1. 子流程 `workflow('article_collect_images')` 相对路径按父脚本目录解析（本项目已支持，无需改）。
2. 脚本内引用的 `.aws-article/config.json`、`aws.env`：以 wechat start 的 cwd 为准准备
   （wx-article/README 写清首次引导；md_to_draft/publish 类需要，outline 类不需要）。
3. `validate` 全量过一遍（CLI 现成）。

### S3 新写 obsidian_outline.js（需求 1）

```text
输入 args: { vaultDir: string（Obsidian 目录 A，必填） }
流程：workflow('article_collect_images', { reference_dir: A/引用文件夹或 A, assets_dir: A/imgs })
   → 图片分析 agent（读图→每图作用→图片引用清单文章，写 A/图片引用清单.md）
   → 目录分析 agent（读 A 全部 md 摘要结构）
   → 大纲 agent（结合清单+目录分析 → A/大纲.md）
输出: { outlinePath, imageListPath, downloadedCount }
```

### S4 Registry 条目（示例）

```json
{
  "workflowId": "obsidian-outline",
  "scriptPath": "scripts/obsidian_outline.js",
  "name": "Obsidian 目录大纲",
  "description": "分析 Obsidian 目录并生成文章大纲：下载引用图片到 imgs、生成图片引用清单",
  "argsSchema": { "type": "object", "properties": { "vaultDir": { "type": "string", "description": "Obsidian 目录绝对路径" } }, "required": ["vaultDir"] },
  "riskLevel": "read-only",
  "enabled": true,
  "keywords": ["obsidian", "目录", "大纲", "引用", "图片", "outline"],
  "examples": ["帮我分析 D:/Obsidian/Notes/A 这个目录做个大纲", "分析这个 obsidian 目录并整理图片引用"]
}
```

wechat_md_to_draft 同款结构（riskLevel=external-side-effect，keywords 含 发布/草稿/公众号）。

### S5 样例集与验证

1. routing-samples 补 4~6 条（中文路径参数抽取是弱项，需真实样例覆盖）。
2. 冒烟链：`pi-workflow validate` → CLI `run`（真实目录）→ `wechat start --registry dev-examples/wx-article/registry.json --scripts dev-examples/wx-article/scripts` → 微信发"帮我分析 <目录> 做大纲"。

## 四、参数抽取注意（路径含空格/中文/盘符）

- argsSchema 把 vaultDir 定为 string；路由 LLM 抽取 Windows 绝对路径（`E:\Obsidian\My Vault\A`）
  需样例覆盖；歧义时走既有 clarify 追问（IR-005）。
- 微信消息里反斜杠/正斜杠都接受（prompt 中声明）。

## 五、顺序建议

与 6 点启动的 WX-PT 并行度：S1~S3 纯文件工作可先行；**S5 微信端到端放在 WX-PT Part B 完成后**
（同一微信号/服务进程，避免测试互相干扰）。发布类微信触发放开依赖 AM-P0 T4（PendingAction）。
