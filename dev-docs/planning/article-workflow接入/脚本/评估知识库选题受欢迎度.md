我刚查了一下 2026 年的内容趋势，这个方向已经明显升温。Karpathy 的 LLM Wiki / AI Second Brain 思路在今年引发了大量讨论，围绕 Obsidian + AI Agent + Markdown 知识库已经出现不少教程和开源项目；例如一个近期的 Second Brain 项目已经有 700+ GitHub Stars。[GitHub+1](https://github.com/NicholasSpisak/second-brain?utm_source=chatgpt.com) 甚至近期一条「20 分钟搭建 AI 第二大脑」的视频，一个月左右已经有约 6 万播放，说明大众对「AI + 个人知识库」确实存在明显兴趣。[YouTube](https://www.youtube.com/watch?v=hOJsRc9Ju7k&utm_source=chatgpt.com)

但我认为真正的机会不在「知识库」三个字，而在下面这个叙事变化：

> **以前：我为什么要记笔记？**  
> ↓  
> **现在：我为什么要给 AI 准备自己的数据？**

这会让你的系列比普通 Obsidian 教程大一个层级。

传统知识管理的问题是：收藏 → 分类 → 打标签 → 搜索 → 自己阅读。现在越来越多实践变成了：原始资料 → AI 整理 → Wiki/知识结构 → AI 检索 → AI 综合 → 写作/工作/决策。近期的 AI Second Brain 实践基本都在往「LLM 维护 Wiki」「AI 自动整理和关联」这个方向走。[Sjoerd van Kersbergen+1](https://sjoerdvankersbergen.nl/tweede-brein/en/?utm_source=chatgpt.com)

所以你前面想到的「**数据飞轮**」其实特别适合成为整个系列的主线：

**信息输入 → AI 整理 → 个人知识库 → AI 调用 → 产生新内容 → 新内容重新进入知识库 → AI 越来越了解你的工作。**

这样一来，你讲的就不是：

> 《Obsidian 从入门到精通》

而是：

> **《从 0 搭建你的 AI 第二大脑：让个人数据形成飞轮》**

这个定位的受众也会明显扩大，不只是程序员，而是普通知识工作者、内容创作者、产品经理、销售、管理者、创业者都能理解。

**ChatGPT:**

可以，而且这类「**同一主题、连续多篇、结构相互依赖**」的内容，反而非常适合用 Workflow 批量生产。

不过我不建议做成：

**10 个标题 → parallel → 10 个 Agent → 一次生成 10 篇文章**

这样虽然快，但很容易出现：第 3 篇和第 6 篇重复、概念定义不一致、前后教程衔接不上、每篇都在重新介绍 Obsidian，以及典型的 AI 味。

更适合你 Dynamic Workflow 的方式是 **「先设计系列，再并行生产，再统一审稿」**：

```
输入
↓
Series Planner
规划整个系列
↓
建立 Series Context
↓
┌──────────────┐
│ 10 篇文章 Brief │
└──────────────┘
↓
并行生成 10 篇
↓
单篇质量检查
↓
系列级 Cross Review
↓
统一修改
↓
输出公众号发布包
```

### 第一阶段：Series Planner

不要直接写文章。先让一个 Agent 输出整个系列的「总设计」。

例如输入：

```
主题：
从零搭建 AI 个人知识库

目标用户：
普通办公人员 / AI 初学者

核心主张：
个人知识库不是记笔记，
而是在给未来的 AI 积累个人数据资产。

系列目标：
让读者从完全不知道知识库，
最终搭建出：
Obsidian + AI + 自动采集 + AI 检索
的个人知识系统。
```

Planner 应该生成一个类似这样的中间产物：

```
series-plan.md

系列核心主张
目标读者
读者最终获得什么

01 为什么需要知识库
02 收藏为什么不等于知识
03 安装 Obsidian
04 设计知识结构
05 自动采集信息
06 AI 自动整理
07 AI 检索
08 AI 问答
09 数据飞轮
10 AI 第二大脑

每篇：
- 核心问题
- 核心观点
- 前置知识
- 新增知识
- 禁止重复内容
- 承接上一篇
- 引出下一篇
```

**这个文件实际上就是整个系列的 Single Source of Truth。**

### 第二阶段：生成 Article Brief

这里不要让 Writer 自己决定写什么。

给每篇文章先生成：

```
articles/
  01/
    brief.md
  02/
    brief.md
  ...
  10/
    brief.md
```

比如第 5 篇：

```
# 05 自动采集信息

目标：
解决“知识库建立以后，东西怎么进去”的问题。

读者状态：
已经安装 Obsidian
已经建立目录结构

本篇新增：
网页 → Obsidian
公众号 → Obsidian
PDF → Obsidian
会议记录 → Obsidian

禁止展开：
RAG
知识图谱
LLM Wiki

因为这些属于后续内容。

上一篇：
04 知识如何分类

下一篇：
06 AI 自动整理
```

这一步非常重要。

**Brief 是控制 10 个并行 Agent 不跑偏的核心。**

### 第三阶段：10 篇并行生产

这时候就特别适合你的 Dynamic Workflow。

概念上可以类似：

```
sequence(
  agent("series-planner"),

  agent("brief-generator"),

  parallel(
    article("01"),
    article("02"),
    article("03"),
    article("04"),
    article("05"),
    article("06"),
    article("07"),
    article("08"),
    article("09"),
    article("10")
  )
)
```

每一个 Article Workflow 内部又可以是：

```
读取 Series Context
+
读取自己的 Brief
↓
Research
↓
Writer
↓
公众号编辑
↓
check
↓
verify
↓
article.md
```

这里其实正好可以用上你之前定义的：

**agent = 干活**

**check/assert = 确定性检查**

**verify = LLM 语义质量检查**

例如：

```
check:
字数 > 2000
必须存在标题
必须存在小标题
必须存在下一篇预告
不能存在空章节

verify:
是否有 AI 味？
是否适合普通人阅读？
是否重复其他文章？
是否符合系列主张？
案例是否容易理解？
有没有真正的信息增量？
```

这会是你 Dynamic Workflow 一个非常好的真实案例。

### 第四阶段一定要增加「系列级 Review」

这是整个 Workflow 最值得做的一步。

10 篇生成结束以后，不是直接发布，而是：

```
10 articles
     ↓
Series Reviewer
     ↓
series-review.md
```

Reviewer 一次读取：

```
Series Plan
+
10 篇文章摘要
+
每篇核心观点
```

检查：

```
重复内容
概念冲突
知识顺序
难度曲线
案例重复
术语一致性
上一篇 → 下一篇衔接
系列核心观点是否逐步建立
```

例如发现：

```
问题：

03、04、05
都用了“第二大脑”的定义。

建议：
只在 01 完整解释。
后续直接引用。

06 提前讲了 RAG，
但 07 才应该正式介绍。

建议：
删除 06 的 RAG 技术细节。
```

然后针对有问题的文章重新调用 Writer。

这实际上已经很接近一个**内容生产 Multi-Agent Pipeline**。

而不是简单的「AI 帮我写文章」。
