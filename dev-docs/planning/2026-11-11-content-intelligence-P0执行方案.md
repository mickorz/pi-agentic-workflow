## 三、关键决策（D1~D10，附倾向）

- **D1 形态**：`SKILL.md`（主流程+规范正文）+ `references/` 三件（content-types / templates / pitfalls）。对齐仓库两件套+引用文档模式；八类定义和模板会持续修订，独立成文件避免撑爆主文件。
- **D2 数据资产位置**：仓库根新建 `content-intelligence/`（samples/ research/ patterns/ analytics/），**git 提交**。理由：样本库是长期资产需版本管理；skill 教流程（规范层），数据目录存产出（资产层），与「skill 不复制数据」原则一致。全部为公开市场信息的分析记录，无隐私问题。
- **D3 taxonomy 归属**：八类内容类型定义放 **skill `references/content-types.md`**（它是判断规范，不是数据）；`patterns/*.md`（标题/开头/结构模式库）放**仓库根数据目录**（它是从样本中沉淀的资产，随研究增长）。
- **D4 搜索策略**：agent 直接用会话内搜索工具，不写脚本。按平台可达性分流（见 5.3 平台清单）；单选题目标样本 ≥20 条，**不足时在报告中明确写「样本不足 N 条及原因」，禁止凑数**。
- **D5 指标纪律与表现分层判定（2026-11-11 评审补充）**：样本模板指标字段固定枚举（views/likes/comments/favorites/shares），每项只能是三种值之一：真实数字（注明采集日期）、`N/A 平台不公开`、`未采集（附原因）`。表现分层（performance.tier）四值：`high 爆款` / `medium 良好` / `normal 普通` / `unknown 无法判断`——**判定必须有数据依据，不能凭内容质量或 AI 主观感觉分类**；不设统一绝对门槛（10w 播放对某账号是普通、对另一账号是爆款），优先用**同平台、同主题/相近主题样本的相对表现**（百分位、互动率）判定，并记录判定基准（performance.basis，如 `same_platform_comparison`）；样本不足以支持相对比较时标 `unknown`，**不强迫每条样本归类**。SKILL.md 和 pitfalls.md 双处写死。
- **D6 与写作线衔接**：`content-intelligence` 的 SKILL.md 写明「研究报告经用户确认后，创作走 gzh-article-craft，content-research.md 作为引用材料输入其 A 定位阶段」；反向指引暂不加到 gzh-article-craft（P0 实测通过后再接，即需求文档第 9 节的落地策略）。
- **D7 幸存者偏差对策（2026-11-11 评审收紧）**：样本库要求**每 ≥5 条爆款至少配 1 条普通表现样本**，且爆款与普通样本必须**同平台、同主题或相近主题**对照（不同平台/主题的对比无效）；研究报告必须含「普通样本为什么没成」小节。
- **D8 样本证据分级（2026-11-11 评审补充）**：每条样本标证据等级——**A**：能读取完整正文、标题、结构和公开表现数据；**B**：能读取正文和标题，表现数据不完整；**C**：只能获取标题、摘要和部分互动数据。20 条是**数量目标，不代表 20 条都具备完整证据**；报告必须统计 A/B/C 分布；关键结论必须引用具体样本；完整正文样本（A 级）过少时必须声明「结论可信度受限」。
- **D9 结论等级四分（2026-11-11 评审补充）**：报告中的每条结论必须标注四级之一——**观察事实**（样本实际呈现的现象）/ **分析判断**（基于样本的解释）/ **策略建议**（下一篇可尝试的方案）/ **待验证假设**（尚未被自己发布数据验证的推测）。禁止把相关性写成因果关系：样本中 12/20 用数字标题只能得出「本次样本中数字型标题出现频率较高」（观察事实），不能得出「数字型标题一定更容易获得高阅读量」。
- **D10 内容形态分层（2026-11-11 评审补充）**：样本加 `content_format` 字段，枚举：`long_article 长文章` / `short_video 短视频` / `image_post 图文卡片` / `tutorial 教程` / `social_post 社交媒体短帖`。传播机制相通但机制落点不同（短视频：前 3 秒抓人/视觉冲击/完播率；公众号长文：标题摘要吸引点击/开头建立阅读动机/章节节奏/收藏转发在看）——**跨格式样本可作灵感来源，不能作为公众号文章的表现基准**，报告中跨格式引用必须显式声明。

### T2 references/content-types.md（八类定义）

- 每类五段：定义与示例题 / 识别特征（标题+结构双特征，供分类时判断）/ 适用选题与读者 / 真实性要求（对应需求文档第 3 节，如故事型禁编造案例）/ 反面模式（如高能冲击型在公众号的标题滥用）
- 复合类型规则：允许「真人故事型+实操教程型」类组合，报告主类型+副类型
- 自查：八类齐全；每类有可操作的「怎么判断一条样本属于这类的标题特征」

### T3 references/templates.md（两套模板）

- **样本记录模板**：YAML 结构（对齐 2026-11-11 评审定案），字段示意：

  ```yaml
  content_format: long_article        # D10 五枚举之一
  evidence:
    level: A                          # D8：A/B/C
    title_verified: true
    full_content_read: true
    metrics_verified: true
  performance:
    tier: high                        # D5：high/medium/normal/unknown
    basis: same_platform_comparison   # 判定基准，unknown 时写 unknown_basis
    metrics:
      views: N/A 平台不公开           # D5 三值规则，数字须注采集日期
      likes: 3200
      comments: 180
      favorites: N/A 平台不公开
      shares: N/A 平台不公开
  analysis:
    observation: "标题使用数字清单结构"      # D9 观察事实
    judgment: "数字与利益点组合出现频率较高"  # D9 分析判断
    hypothesis: "数字清单可能提升点击意愿"   # D9 待验证假设
  ```

  另含：原始链接/平台/作者/发布时间/内容类型（八类）/采集日期/标题·开头·正文结构/传播机制/借鉴点/不模仿点（需求文档第 5 节全字段）。
- **content-research.md 报告模板**：章节 = ①选题与目标读者 ②搜索过程（关键词/平台/日期/命中情况）③样本清单表（含 evidence level / performance tier / content_format 列）④八类分布统计 + **A/B/C 证据分布统计（D8）** ⑤六维拆解（标题/开头/结构/价值/传播/差异化，跨格式样本引用须显式声明，D10）⑥普通样本对比分析（D7 同平台同主题）⑦≥3 个可执行内容方向（每条标 D9 策略建议级）⑧**结论可信度声明**（A 级样本占比过低时声明受限，D8）⑨人工确认清单（选题方向/内容类型/标题策略三项待用户拍板）。全文结论逐条标 D9 四级（观察事实/分析判断/策略建议/待验证假设）。
- 自查：模板字段与需求文档第 5 节样本字段逐条对齐，无遗漏；四个评审补充字段（content_format/evidence/performance/analysis）齐全

### T4 references/pitfalls.md（坑清单）

首批条目（现象+一句话解法，对齐仓库坑清单风格）：

1. 指标编造——LLM 见过大量「10w+」语料会顺手编数字；解法：D5 三值枚举，宁空勿编
2. 跨平台不可比——短视频播放量 vs 公众号阅读量直接排序；解法：样本表按平台分组，报告结论限平台内有效
3. 幸存者偏差——只收爆款导致模式过拟合；解法：D7 的 5:1 配额 + 普通样本分析小节
4. 搜索样本同质化——同一篇爆文被多个渠道转载计为多条；解法：按原始出处去重，转载链接并入备注
5. 确认门被跳过——研究完顺手开写；解法：SKILL.md 流程表把「人工确认」设为硬停节点，产出物不含正文任何章节
6. 证据虚假完整——搜到 20 条链接只真读过 3 篇，仍生成看似完整的报告；解法：D8 证据分级逐条标注 + A/B/C 分布统计 + A 级过少声明可信度受限
7. 相关性当因果——把样本频率（12/20 用数字标题）写成因果结论（数字标题带来高阅读）；解法：D9 结论等级四分，报告逐条标注，推测一律进「待验证假设」不进结论

## 六、验收标准与验收方式（P0 六条逐条对应）

| # | 验收标准（需求文档第 7 节） | 验收方式 |
|---|---|---|
| 1 | 输入选题可找到 ≥20 条相关样本，不足时明确报告 | 数 samples/ 登记条数；报告含「样本充足性声明」段；附 A/B/C 证据分布统计（D8） |
| 2 | 能区分八种内容类型 | 样本表每条有类型字段；报告有八类分布统计；抽查 3 条分类依据成立 |
| 3 | 能提炼标题、开头、结构和传播机制 | 报告六维拆解章节四项齐全，且引用具体样本（带链接）作证 |
| 4 | 能给出 ≥3 个可执行内容方向 | 报告第⑦章 ≥3 条，每条含：类型 / 切入角度 / 差异化理由 / 可执行性说明 |
| 5 | 生成完整研究报告 | 报告模板⑧章全部非空；落盘于 content-intelligence/research/ |
| 6 | 不直接开始写文章，必须人工确认 | 全程无正文章节产出；报告以「人工确认清单」结尾；用户确认记录在案 |

附加纪律核对（一票否决项）：

- 任意样本指标字段出现无出处的数字 → 不通过（D5）
- 表现分层凭内容质量或 AI 主观感觉标注、无数据依据 → 不通过（D5）
- 报告把不同平台指标混排得出结论，或跨格式样本直接作表现基准 → 不通过（pitfall 2 / D10）
- 爆款样本无同平台同主题普通样本对照 → 不通过（D7）
- 关键结论无具体样本引用，或推测性结论未标「待验证假设」直接写成事实 → 不通过（D8 / D9）

## 七、风险与经验引用

| 风险 | 应对 |
|---|---|
| 微信公众号生态内容大多抓不到正文与阅读量（反爬+登录墙） | 搜索分流到知乎/掘金/少数派/GitHub/B站/YouTube/博客等可达平台；公众号文章仅作选题参考不进样本表（进不去就换源，不硬爬不编造） |

| LLM 把相关性写成因果、把主观偏好当爆款判定 | D9 结论等级四分逐条标注 + D5 分层判定要数据依据 + pitfalls 6/7 条 |
| 研究完直接开写、确认门被跳过 | pitfalls 第 5 条：SKILL.md 硬停节点设计，产出物不含正文 |
| 样本越攒越乱、无法复用 | samples 按主题域子目录（ai-agent/ ai-tools/ enterprise-ai/ programming/），patterns 从样本回填而非凭空写 |

# P0.1 渠道架构调整（2026-11-11 第二轮评审定案）

> 评审触发：T6 首测元发现——23 条样本全部来自技术社区/通用网络，却要指导公众号创作。**渠道错位**：研究了 CSDN/知乎，想指导的却是公众号/小红书/抖音。

## P0.1-D11 研究渠道权重（研究资源配置，非证据可信度评分）

| 渠道 | 研究权重 | 定位 |
|---|---|---|
| 微信公众号 | 45% | 长文主阵地：同赛道文章、同行账号、爆款与普通文章；标题/开头/结构/阅读分享 |
| 小红书 | 30% | 痛点表达：图文笔记、搜索结果、评论区；封面/标题/赞藏比/评论痛点 |
| 抖音 | 15% | 表达机制：口播/知识短视频；前3秒钩子/结构/互动 |
| 其他（知乎/CSDN/技术博客等） | 10% | 事实与技术素材来源，只做补充 |

两条独立维度：**研究权重**决定时间与采集预算；**证据权重**由 evidence level 独立决定（公众号一篇只有标题的 C 级样本，不因 45% 权重而比技术社区 A 级全文更可信）。

## P0.1-D12 平台适配器架构

- 统一样本 Schema（所有平台同一套字段：来源/原文/表现指标/证据等级/采集时间/采集方式）
- `references/platform-profiles.md`：每平台一套分析规范（platform_profile），六维分析保留、规则按平台差异化
- 对照组纪律强化：爆款 vs 普通只能在**平台、内容格式、发布时间、账号规模、选题**五个变量受控的组内比较（comparison_group 字段落地）
- **跨平台只迁移内容机制，不迁移表现结论**：小红书评论区痛点是调查线索，不构成公众号阅读量预期
- 三种采集模式，任一平台采集失败不拖垮研究流程：**自动**（合法公开页面/接口）/ **半自动**（人工站内搜索导出候选，agent 分析）/ **人工导入**（截图/链接/正文/已授权数据交给 skill 分析）；每样本记录 collection_method 与缺失字段

## P0.1-D13 阶段推进

- **P0.1-T2 采集可行性实测先行**（用户指定优先）：三平台各 5 条真实作品，验证可获取字段/采集成本/失败原因；先验证能力，再定自动化方案
- 第三方数据服务（新榜/清博/千瓜/新红/蝉妈妈/飞瓜）：P1 逐项评估覆盖范围/授权方式/导出能力/费用，不默认有开放 API
