> 日期：2026-11-11

> 定位：只做 P0——新建 `content-intelligence` skill，验证「先研究再写」能否改善选题与标题质量；**不改 gzh-article-craft、不注册 workflow、不做 Gate B**（不走微信入口，无需 mock 验收）。

## 一、目标与不做的事

**目标**：新建 `.pi/skills/content-intelligence/`，仅凭该 skill 可完整引导一次「选题 → 市场搜索 → 样本收集 → 八类分类 → 六维拆解 → content-research.md → 人工确认」，并让样本沉淀进仓库数据目录。拿一篇真实 AI 主题文章实测通过 P0 六条验收。

**不做（明确排除，P1/P2 再议）**：

- 不改 `gzh-article-craft` 任何文件（衔接只做 skill 内单向指引，见 D6）
- 不注册 workflow / 不动 Router、Registry、授权、执行器（无 Gate B 义务）
- 不写爬虫、不建数据库、不做 Dashboard（需求文档第 6 节明确 P0 不做）
- 不做 `content-performance-analysis`（P2：读公众号后台数据）
- 不追求自动化指标采集——公众号阅读量等不可得数据**留空标 N/A，禁止编造**

## 三、关键决策（D1~D7，附倾向）

- **D1 形态**：`SKILL.md`（主流程+规范正文）+ `references/` 三件（content-types / templates / pitfalls）。对齐仓库两件套+引用文档模式；八类定义和模板会持续修订，独立成文件避免撑爆主文件。
- **D2 数据资产位置**：仓库根新建 `content-intelligence/`（samples/ research/ patterns/ analytics/），**git 提交**。理由：样本库是长期资产需版本管理；skill 教流程（规范层），数据目录存产出（资产层），与「skill 不复制数据」原则一致。全部为公开市场信息的分析记录，无隐私问题。
- **D3 taxonomy 归属**：八类内容类型定义放 **skill `references/content-types.md`**（它是判断规范，不是数据）；`patterns/*.md`（标题/开头/结构模式库）放**仓库根数据目录**（它是从样本中沉淀的资产，随研究增长）。
- **D4 搜索策略**：agent 直接用会话内搜索工具，不写脚本。按平台可达性分流（见 5.3 平台清单）；单选题目标样本 ≥20 条，**不足时在报告中明确写「样本不足 N 条及原因」，禁止凑数**。
- **D5 指标纪律落地**：样本模板指标字段固定枚举（views/likes/comments/favorites/shares），每项只能是三种值之一：真实数字（注明采集日期）、`N/A 平台不公开`、`未采集（附原因）`。SKILL.md 和 pitfalls.md 双处写死这条。
- **D6 与写作线衔接**：`content-intelligence` 的 SKILL.md 写明「研究报告经用户确认后，创作走 gzh-article-craft，content-research.md 作为引用材料输入其 A 定位阶段」；反向指引暂不加到 gzh-article-craft（P0 实测通过后再接，即需求文档第 9 节的落地策略）。
- **D7 幸存者偏差对策**：样本库要求**每 ≥5 条爆款至少配 1 条普通表现样本**（同平台同主题），模板加「表现分层」字段（爆款/良好/普通）；研究报告必须含「普通样本为什么没成」小节。

## 五、任务拆解

### T1 数据目录骨架

- 建仓库根 `content-intelligence/` 四个子目录 + 各 README（职责一句话 + 登记规则速查 + N/A 纪律）
- `patterns/*.md` 放空表头种子（字段：模式名 / 出处样本链接 / 适用类型 / 注意点），**不预填虚构模式**
- 自查：目录树与本方案第四节一致；README 里 N/A 纪律可检索到

### T2 references/content-types.md（八类定义）

- 每类五段：定义与示例题 / 识别特征（标题+结构双特征，供分类时判断）/ 适用选题与读者 / 真实性要求（对应需求文档第 3 节，如故事型禁编造案例）/ 反面模式（如高能冲击型在公众号的标题滥用）
- 复合类型规则：允许「真人故事型+实操教程型」类组合，报告主类型+副类型
- 自查：八类齐全；每类有可操作的「怎么判断一条样本属于这类的标题特征」

### T3 references/templates.md（两套模板）

- **样本记录模板**：字段 = 需求文档第 5 节全字段 + 表现分层（爆款/良好/普通）+ 采集日期 + 指标枚举纪律（D5 三值规则）
- **content-research.md 报告模板**：章节 = ①选题与目标读者 ②搜索过程（关键词/平台/日期/命中情况）③样本清单表 ④八类分布统计 ⑤六维拆解（标题/开头/结构/价值/传播/差异化）⑥普通样本对比分析（D7）⑦≥3 个可执行内容方向 ⑧人工确认清单（选题方向/内容类型/标题策略三项待用户拍板）
- 自查：模板字段与需求文档第 5 节样本字段逐条对齐，无遗漏

### T4 references/pitfalls.md（坑清单）

首批条目（现象+一句话解法，对齐仓库坑清单风格）：

1. 指标编造——LLM 见过大量「10w+」语料会顺手编数字；解法：D5 三值枚举，宁空勿编
2. 跨平台不可比——短视频播放量 vs 公众号阅读量直接排序；解法：样本表按平台分组，报告结论限平台内有效
3. 幸存者偏差——只收爆款导致模式过拟合；解法：D7 的 5:1 配额 + 普通样本分析小节
4. 搜索样本同质化——同一篇爆文被多个渠道转载计为多条；解法：按原始出处去重，转载链接并入备注
5. 确认门被跳过——研究完顺手开写；解法：SKILL.md 流程表把「人工确认」设为硬停节点，产出物不含正文任何章节

### T5 SKILL.md 主文件

- frontmatter：`name: content-intelligence`，description 含触发词（选题研究/内容调研/爆款分析/写之前先研究）+「Use when 用户要研究一个选题的市场表现、收集爆款样本、做写作前数据分析」
- 正文结构：
  1. 术语与路由边界：本 skill 只产出研究报告，不产文章正文；创作一律转 `gzh-article-craft`（D6 单向指引）；小绿书走 `xiaolvshu`
  2. 流程总览表（七步）：定读者与方向 → 搜索 → 收样本 → 八类分类 → 六维拆解 → 机会分析 → 报告落盘 + **人工确认门（硬停）**
  3. 各步规范：搜索关键词策略（选题词+平台词+表现词组合）/ 样本 ≥20 条与不足报告（D4）/ 样本落盘路径（content-intelligence/samples/<主题域>/）
  4. 数据纪律专节：D5 三值枚举、来源+采集日期必填、禁止把不可公开访问数据伪装成统计结果
  5. 验收对照：P0 六条标准内嵌为「交付前自查清单」
- 自查：对照需求文档第 4/7/8 节，七步、六维、八类、确认门全部覆盖

### T6 实测验收（真实选题跑通）

- 选一个真实待写选题（候选：需求文档第 6 节选题 A「企业沉睡数据变 AI 生产力」，需用户最终拍板）
- 全流程执行：产出首份 `content-intelligence/research/<日期>-<主题>.md` + `samples/` 下 ≥20 条样本记录
- 逐条核对 P0 六条验收标准（见第六节验收表），结果记入进度文档
- 用户过目研究报告并确认/否决内容方向——**用户确认行为本身就是验收第 6 条的证据**

### T7 收尾归档

- 新定案偏好（若有）登记 `preference.md` 并注明日期
- 进度更新：`dev-docs/progress/执行进度.md` 里程碑表 + 本阶段条目；执行报告按规范新建 `dev-docs/progress-result/` 阶段报告（不追加其他阶段文件）
- git commit + push（按仓库约定主动提交，不询问）

### 执行顺序与依赖

T1 → T2/T3/T4（可并行）→ T5 → T6 → T7。T6 必须在全部文档就绪后执行；T6 需用户参与（选题拍板 + 报告确认），开工前先问一次。

## 六、验收标准与验收方式（P0 六条逐条对应）

| # | 验收标准（需求文档第 7 节） | 验收方式 |
|---|---|---|
| 1 | 输入选题可找到 ≥20 条相关样本，不足时明确报告 | 数 samples/ 登记条数；报告含「样本充足性声明」段 |
| 2 | 能区分八种内容类型 | 样本表每条有类型字段；报告有八类分布统计；抽查 3 条分类依据成立 |
| 3 | 能提炼标题、开头、结构和传播机制 | 报告六维拆解章节四项齐全，且引用具体样本（带链接）作证 |
| 4 | 能给出 ≥3 个可执行内容方向 | 报告第⑦章 ≥3 条，每条含：类型 / 切入角度 / 差异化理由 / 可执行性说明 |
| 5 | 生成完整研究报告 | 报告模板⑧章全部非空；落盘于 content-intelligence/research/ |
| 6 | 不直接开始写文章，必须人工确认 | 全程无正文章节产出；报告以「人工确认清单」结尾；用户确认记录在案 |

附加纪律核对（一票否决项）：

- 任意样本指标字段出现无出处的数字 → 不通过（D5）
- 报告把不同平台指标混排得出结论 → 不通过（pitfall 2）
- 爆款样本无普通样本对照 → 不通过（D7）

## 七、风险与经验引用

| 风险 | 应对 |
|---|---|
| 微信公众号生态内容大多抓不到正文与阅读量（反爬+登录墙） | 搜索分流到知乎/掘金/少数派/GitHub/B站/YouTube/博客等可达平台；公众号文章仅作选题参考不进样本表（进不去就换源，不硬爬不编造） |
| 搜索结果被 SEO 农场污染，「高表现」判断失真 | 六维拆解不只看指标，重点看内容结构是否真实成立（真实性要求在 content-types.md 每类内置） |
| LLM 顺手编造指标数据 | D5 三值枚举 + pitfalls 首条 + 交付自查清单，三层拦 |
| 研究完直接开写、确认门被跳过 | pitfalls 第 5 条：SKILL.md 硬停节点设计，产出物不含正文 |
| 样本越攒越乱、无法复用 | samples 按主题域子目录（ai-agent/ ai-tools/ enterprise-ai/ programming/），patterns 从样本回填而非凭空写 |

平台可达性速查（T5 写进 SKILL.md）：

- **可直接读**：掘金、知乎（部分）、少数派、GitHub、独立博客、B站（播放量公开）、YouTube（播放量公开）、Hacker News
- **部分受限**：Medium（付费墙，元数据可读）、Twitter/X（登录墙，部分快照可读）
- **基本不可得**：微信公众号阅读量（只有 10w+ 档）、小红书（强登录墙）——指标一律 `N/A 平台不公开`
