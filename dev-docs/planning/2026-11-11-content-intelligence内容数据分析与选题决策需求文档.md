# Content Intelligence 内容数据分析与选题决策 — 需求文档

> 日期：2026-11-11
> 状态：需求已定稿，待拆解执行方案（P0 优先）
> 关联：`.pi/skills/gzh-article-craft/`（现有文章生产链路，本需求不改其内部流程）

## 0. 一句话定位

把「AI 辅助写文章」升级为「数据驱动的内容生产系统」：**先研究市场上什么内容有效，再决定写什么、怎么写，最后才进入 AI 创作**。

核心观点（源自用户参考视频）：

> 不要先问自己喜欢写什么，而要先研究目标读者愿意看什么。

注意事项（写进原则）：

- 爆款标题 ≠ 好文章，播放量 ≠ 转化效果。分析的不只是流量，还包括读者是否愿意收藏、转发，以及能否建立专业信任。
- 不能拿 100 万播放的短视频和 5000 阅读的公众号文章直接比较；应在相同平台、相近发布时间、相似主题和内容形式下比较。
- 公开指标（播放/点赞/评论）只是表现代理，不能直接证明因果效果。
- 无法获取的阅读量/播放量不允许 AI 猜测，不得把无法公开访问的数据伪装成真实统计结果。

## 1. 背景与账号定位

本仓库公众号主要面向 **企业老板、AI 负责人**，内容方向：AI 应用落地、Agent、WorkBuddy、企业工作流。选题不能只根据自己对技术的兴趣决定，需要市场数据研究支撑。

## 2. 现状与缺口

现有 `gzh-article-craft` 生产链路（保留不动）：

1. 定位讨论：三问、引用材料提炼、差异化定位、10 个 GEO 标题候选
2. 文章大纲：钩子、是什么、实测论证、方法、冷思考、行动收尾
3. 逐章写作：一章一确认，实时落盘
4. 配图制作：提示词、审批、生图、图片核对
5. 质量检查：Humanizer、事实核对、排版预览
6. 发布：进入草稿箱，人工发布

**缺口**：现有流程擅长把一篇文章写好，但没解决「为什么写这篇文章、读者为什么会点击」。

| 当前做法 | 新增做法（Content Intelligence） |
| --- | --- |
| 读取用户提供的文章 | 主动寻找同类优质内容 |
| 提炼文章的知识点 | 分析内容为什么受欢迎 |
| 生成 10 个标题 | 从验证过的标题结构中生成 |
| AI 自己组织大纲 | 根据目标读者和内容类型选择结构 |
| 主要检查文章质量 | 同时检查内容价值和传播潜力 |

结论：**保留现有创作流程，在其前面增加独立的「写作前数据分析」阶段**。

## 3. 内容类型库（八类，先分类再选写法）

八种类型不是八套固定文章模板，而是八套不同的内容组织策略：

| # | 类型 | 示例 | 核心 |
| --- | --- | --- | --- |
| 1 | 数字盘点型 | 2026 年值得关注的 7 个 AI Agent 工具 | 数字、清单、收藏价值 |
| 2 | 高能冲击型 | 未来的软件公司，可能不再招前端和后端了 | 反常识、冲突、趋势变化 |
| 3 | 点名观众型 | 如果你是企业技术负责人，这 5 个 AI 能力必须了解 | 身份代入、精准受众 |
| 4 | 对比测评型 | OpenCode 和 Claude Code，企业开发应该怎么选 | 对立、差异、决策帮助 |
| 5 | 需求场景型 | 企业有大量历史文档，怎样让 AI 真正用起来 | 痛点、解决方案、落地价值 |
| 6 | 真人故事型 | 一个程序员，如何用 AI 一个人完成过去一个团队的工作 | 人物、过程、结果、经验 |
| 7 | 实操教程型 | 从零搭建一个可以自动执行任务的 Agent | 步骤、代码、可复现、实用性 |
| 8 | 观点分析型 | AI Agent 普及之后，程序员真正需要提升的是什么 | 独立判断、专业认知、观点差异 |

各类型的真实性要求：

- 数字盘点型：清单内容真实有价值
- 对比测评型：有真实的比较维度
- 真人故事型：真实人物和经历，不能编造案例
- 实操教程型：有实际操作和验证结果
- 观点分析型：有自己的判断，不是汇总别人观点

特别纪律：短视频的「高能冲击型」可借鉴其开头机制，但公众号文章不应全部写成夸张标题。

## 4. 新的文章生产架构

```
用户输入选题 / 灵感 / 参考文章
        │
        ▼
┌─────────────────────────────────────┐
│ Content Intelligence · 内容数据分析  │ （新增阶段）
│ 1. 确定目标读者和选题方向            │
│ 2. 搜索同类型文章、视频和案例        │
│ 3. 收集高表现内容样本                │
│ 4. 将样本分类为八种内容类型          │
│ 5. 分析标题、开头、结构、传播机制    │
│ 6. 总结可借鉴模式与内容机会          │
│ 7. 生成数据分析报告                  │
│ 产物：content-research.md            │
│ 人工确认：选题方向、内容类型、标题策略│
└─────────────────────────────────────┘
        │
        ▼
gzh-article-craft（原有流程，不改）
文章定位 → 标题生成 → 大纲 → 逐章写作 → 配图审核 → 草稿箱
        │
        ▼
发布 + 数据反馈 + 内容策略迭代
```

### 4.1 六个分析维度

| 维度 | 分析内容 |
| --- | --- |
| 标题 | 数字、利益、痛点、冲突、身份代入 |
| 开头 | 如何在前 3 段留住读者 |
| 内容结构 | 清单、对比、故事、教程、观点 |
| 内容价值 | 解决什么问题，提供什么增量 |
| 传播机制 | 为什么值得收藏、转发、讨论 |
| 差异化 | 同类内容已写了什么，还有什么没写 |

## 5. 爆款样本数据库（长期价值最大的部分）

每次选题研究不只生成报告，还要把结果沉淀下来：

```
content-intelligence/
├── taxonomy/
│   └── content-types.md          # 八类内容类型定义
├── samples/                      # 市场样本（按主题域分目录）
│   ├── ai-agent/
│   ├── ai-tools/
│   ├── enterprise-ai/
│   └── programming/
├── research/                     # 每次研究的报告
│   ├── 2026-11-11-ai-agent.md
│   └── 2026-11-12-ai-workflow.md
├── patterns/
│   ├── title-patterns.md         # 标题结构库
│   ├── opening-patterns.md       # 开头结构库
│   └── structure-patterns.md     # 正文结构库
└── analytics/
    └── published-content-performance.json  # 自己公众号的发布数据
```

每条样本记录字段：

- 原始链接、平台、作者
- 标题、发布时间、内容类型（八类之一）
- 可获取的播放量、阅读量、点赞量、评论量、收藏量（**获取不到就留空，禁止编造**）
- 标题结构、开头结构、正文结构
- 核心传播机制
- 值得借鉴的部分 / 不适合直接模仿的部分

两条纪律：

1. **不只保存爆款，也保存普通表现的内容**，否则产生幸存者偏差（只看到成功案例，不知道同样写法有多少失败了）。
2. **「公开市场样本」与「自己公众号发布数据」分开**：前者用于研究市场，后者才是检验自己内容策略是否有效的真实依据。

## 6. 应用示例（三个近期选题）

| 选题 | 类型 | 目标读者 | 研究对象 | 内容策略 |
| --- | --- | --- | --- | --- |
| A. 企业沉睡的数据，如何变成 AI 生产力 | 需求场景型 | 企业老板、AI 负责人 | 企业知识库、RAG、数据清洗、Agent 落地案例 | 痛点切入 → 真实案例 → 数据处理流程 → 实施建议 |
| B. 未来的软件公司，可能不再招前端和后端了 | 高能冲击型 | 程序员、技术负责人 | AI Coding、Agentic Engineering、岗位变化 | 反常识观点 → 现实证据 → 工作方式变化 → 我的判断 |
| C. 我用 AI 搭建了一个自动化公众号生产工作流 | 真人故事型 + 实操教程型 | 独立开发者、AI 应用开发者 | 个人 Agent、内容自动化、工作流编排 | 真实需求 → 开发过程 → 架构拆解 → 实际效果 → 经验总结 |

补充优势：本仓库 `pi-agentic-workflow` 的真实开发过程、踩坑记录、架构设计本身就是内容资产，比追逐网络爆款更容易建立专业辨识度。

## 7. 分阶段计划

| 阶段 | 工作 | 交付 |
| --- | --- | --- |
| P0 | 新增内容研究 Skill：搜索、样本收集、分类和分析 | content-research.md |
| P1 | 建立八类内容策略库、标题结构库和样本库 | Content Intelligence Library |
| P2 | 记录公众号发布数据，分析不同类型文章的实际表现 | 内容策略反馈系统 |

### P0 验收标准

1. 输入一个选题，可找到至少 20 条相关样本（不足时明确报告，不凑数）。
2. 能区分八种内容类型。
3. 能提炼标题、开头、结构和传播机制。
4. 能给出至少三个可执行的内容方向。
5. 能生成一份完整的研究报告。
6. **不直接开始写文章，必须经过人工确认**。

数据纪律：搜索时记录样本来源和采集日期；无法获取的阅读量、播放量不猜测；不把无法公开访问的数据伪装成真实统计结果。

## 8. Skill 边界划分

**不把功能塞进 `gzh-article-craft`**，采用独立 Skill：

| Skill | 职责 |
| --- | --- |
| `content-intelligence`（新增） | 选题研究、爆款样本收集、八类分类、标题与结构拆解、内容机会分析、输出研究报告 |
| `gzh-article-craft`（现有） | 读取研究报告、选择内容策略、生成标题和大纲、文章写作、配图排版审核、草稿发布 |
| `content-performance-analysis`（未来 P2） | 读取公众号后台历史数据，回答：哪类文章更易获得推荐、哪种标题点击更好、哪种更易被转发、哪些低阅读但吸引精准读者、下一阶段增加哪类内容 |

### 自优化飞轮

```
市场数据研究（别人什么内容有效）
  → 内容策略选择（选合适的类型和结构）
  → AI 辅助创作（生产有差异化的原创内容）
  → 发布与效果追踪（自己的真实阅读、转发、推荐数据）
  → 反馈到下一轮内容研究
```

## 9. 落地策略

**先做 P0，暂不改动现有公众号生产链路。**

1. 建立独立的 `content-intelligence` Skill。
2. 拿下一篇 AI 主题文章实测，对比「直接让 AI 写」和「先做数据研究再写」的效果。
3. 若研究报告确实帮助找到更好的切入角度，再正式接入 `gzh-article-craft` 入口。

这样既不破坏已稳定的生产流程，也能逐步完成升级。
