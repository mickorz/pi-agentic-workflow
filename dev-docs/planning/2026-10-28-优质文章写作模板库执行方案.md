5. **审稿结构化问题对象与终态联动**：`templateCheck.issues`/`factCheck.unsupportedClaims` 统一为 `{code, message, blocking, repairable}`；修复循环只吃 `repairable: true` 的阻断项；不可修复项保留"待人工核实"清单进 `6-review.md` 与交接播报，不烧修复轮次；明确 `draft_ready` 终态判定。
6. **验收加强**：6 项场景扩至 9 项（YAML 落盘往返、修改文章模板继承、首次绑定中途崩溃）；P2 并发测试改双独立进程；内容对照扩至 2-3 个选题并定通过标准。

## 一、目标与不做的事

**目标：**

1. 建立**写作模板库**（文件目录 + README 索引），沉淀优质文章的章节功能、叙事逻辑、语气、案例用法、质量规则，形成带来源和版本的可复用 Markdown 模板。
2. 写作链支持**手动指定模板**：确定性读取、版本锁定、断点恢复一致、修改文章继承、审稿增项不破坏既有契约。
3. （条件启动）**模板提取 Workflow**：确定性读入优质文章 → agent 结构提炼 → 程序化校验落盘草稿 → 人工审核入库。
4. 理清**三类资产边界**：写作模板（怎么讲）/ 排版模板（怎么展示）/ 视觉生图模板（图片怎么设计），已有资产只登记互链不重建。

**不做（本方案明确排除）：**

- 不建模板管理平台/数据库/服务：目录 + Markdown + README 索引就是全部。
- 不做自动模板推荐、多模板组合、效果 A/B 对比、自动优化（第一版范围收紧为手动单模板）。
- 不做模板迁移（已绑定任务换模板 = 新建任务）。
- 不重建排版模板（已有 presets）与视觉生图模板（已有 image-styles / visual 规则）。
- 不复制原文：模板只含结构与规则，禁止出现原文内容片段。
- 不改写作链默认行为：不传 `template` 参数时链路行为与现状完全一致。
- 不扩 `idea_files.py` 的文件读写范围：模板资产走独立的 `template_store.py`（仅 state 双白名单两处最小改动）。

## 三、模板资产规范

### 3.1 目录与文件职责（V1.2 定版：指针与正文分离）

```
dev-examples/wx-article/
├── writing-templates/
│   ├── README.md                      # 索引表 + 三类资产边界 + 本节规范落档
│   ├── t-001-case-dissection.md       # 指针文件（仅元数据，无正文）
│   └── versions/
│       └── t-001/
│           ├── v1.md                  # 不可变的七节模板正文
│           └── v2.md
└── scripts/
    ├── template_store.py              # 模板确定性读写器（见 3.6）
    └── template_store_Example.py      # 自检脚本
```

**职责表（定版）：**

| 文件 | 存什么 | 可变性 |
|------|--------|--------|
| `t-001-case-dissection.md`（指针） | frontmatter：`template_id` / `name` / `status` / `current_version` / `current_sha256` / `applicable` / `source_article` | **可变**：仅 status 与 current_* 随审核/升级变更 |
| `versions/t-001/vN.md`（版本文件） | frontmatter（`template_id`/`version`/`sha256`/`extracted_at`）+ 七节正文 | **不可变**：写入后永不修改、永不删除 |

规则：

- `read-active` 两段读：读指针 → 校验 `status: active` → 按 `current_version`/`current_sha256` 读版本文件 → 校验哈希一致 → 返回正文。
- **status 转换（draft→active、retire）只改指针**；绝不为转 active 而修改版本文件。
- 升级产生新版本文件（`v{N+1}.md`），`allocate-id` 保证 ID 不变；P2 草稿落新版本文件，**不覆盖当前 active 版本**。
- `template_id` 与 `version` 分开管理；旧版本永不覆盖删除，任务快照按 sha256 可溯源到版本文件。

### 3.2 模板正文格式（七节，存于版本文件）

```markdown
---
template_id: t-001
version: v1
sha256: "<本文件正文哈希>"
source_article: <文章标题>（<路径或链接>，发布日期）
extracted_at: YYYY-MM-DD
---

## 一、适用与不适用
## 二、章节功能序列   # 表格：序号 | 章节 | 功能 | 篇幅占比
## 三、叙事逻辑
## 四、语气与文风
## 五、案例与论据用法 # 只写类型与用法，不写案例本身
## 六、质量规则
## 七、结构骨架       # 占位符形态，与既有 structure-template 兼容
```

状态纪律：指针 `status` ∈ `draft | active | retired`；`draft` → 人工审核通过才改指针为 `active`；只有 `active` 可被写作链选用；任何自动化环节不得改 status。

**哈希规则（定版）**：sha256 只计算七节正文的 UTF-8 字节，换行符统一 LF，不含 frontmatter（避免 Windows/Mac CRLF 差异与把 `sha256` 字段本身纳入计算的自引用）；指针 `current_sha256`、版本文件 `sha256`、任务快照哈希三处同源同规则。

### 3.3 防抄袭铁律（不变）

1. 模板只含结构与规则，禁止出现原文具体内容（案例原文、金句原文、数据、专有段落、语句片段）。
2. "案例与论据用法"只写类型与功能，不写案例内容。
3. 结构骨架示例一律用占位符。
4. 提取产物一律以 `draft` 落盘，人工审核后才转 `active`。

### 3.4 名称→ID 解析规则（确定性，不变）

- 用户话术给中文模板名，Router 提取 `template` 参数为名称或 ID 均可。
- 解析在 `template_store.py resolve` 内确定性完成：精确 ID 命中 > name 唯一命中；重名、多命中、无命中一律拒绝并返回候选清单，不做模糊猜测。

### 3.5 模板绑定与继承规则（V1.2 新增，修改文章分支已核实）

**首次绑定判定：state（article.yaml）中是否存在 `writingTemplate` 绑定，不是任务状态名**——因为 `modifyM` 会把 status 回退 `brief_confirmed` 全链重生成，看状态名会导致重复绑定/覆盖快照。

| 场景 | 规则 |
|------|------|
| 首次绑定（state 无 `writingTemplate` 且 `args.template` 有值，且 status=`brief_confirmed` 大纲未生成） | resolve → read-active → snapshot 落任务目录 → state 写三键 |
| **首次绑定但大纲已存在**（`outline_generated`/`drafting`/`reviewing`/`draft_ready` 无绑定却传 `template`） | **明确拒绝**：提示"本文大纲已在普通模式生成，套模板请新建任务"，防止普通大纲 + 模板正文混版，不允许中途隐式切换写作模式 |
| 已绑定，修改文章（modifyM 回退 brief_confirmed） | **沿用原快照**，跳过绑定阶段，不重新 snapshot、不换版本 |
| 已绑定，`args.template` 与已绑 ID 不同 | **明确拒绝**并说明"该文章已绑定模板 X，换模板请新建任务"，不覆盖 |
| 已绑定，生成大纲后想换模板 | 拒绝（同上）；V1 不做模板迁移 |
| 未绑定，`args.template` 为空 | 原写作链行为，不绑定、不写 state 键 |

### 3.6 `template_store.py`（确定性读写器，不扩 idea_files.py 权限）

子命令（全部确定性、零 LLM、仅标准库；stdout `{ok:...}` JSON 契约）：

| 子命令 | 职责 | 关键校验 |
|--------|------|---------|
| `allocate-id` | 分配下一 template_id | `O_EXCL` 原子创建占位文件，防并发冲突（P2 加双进程并发测试） |
| `resolve` | 名称/ID → template_id | 重名/歧义/无命中拒绝，返回候选 |
| `read-active` | 指针→版本文件两段读 | 指针 status=active 校验、current_sha256 与版本文件一致性、路径越界拒绝、符号链接拒绝 |
| `snapshot` | 快照写入任务目录 | 按 sha256 落盘；已存在且 hash 一致返回 SKIP，不一致报错（不可变） |
| `restore` | 任务续写时校验快照 | 快照 sha256 与 state 三键一致才放行，返回快照内容 |
| `save-draft`（P2） | 原子写入 draft 新版本文件 | 防重复（同源文章 hash 命中拒绝）、相似度阈值预检、原子写、不覆盖 active |
| `similarity`（P2） | 程序化相似度检测 | 字符 n-gram 重叠率，超阈值 FAIL |
| `read-source`（P2） | 读待分析文章 | 路径/大小/编码校验，返回纯文本（不可信素材） |

安全约束沿用 idea_files 同款手法：`resolve_dir` 式目录锁定、符号链接拒绝、大小上限、原子写。

### 3.6.1 快照与状态绑定的恢复契约（V1.2 新增）

绑定顺序固定为：先 `snapshot` 后 `state --set`。两步非原子，中断后按此表确定性处理：

| 快照 | state 绑定 | 处理 |
|------|-----------|------|
| 不存在 | 不存在 | 正常首次绑定 |
| 存在且一致 | 存在 | 正常恢复（用快照续写） |
| 存在 | **不存在** | 未完成绑定：若 `args.template` 与快照 sha256 来源一致 → 用现有快照补绑（安全恢复）；不一致或无 template 参数 → 明确中止并报告，**不静默覆盖** |
| 不存在 | 存在 | 中止并报告快照缺失（不自动重建） |
| 存在但哈希不一致 | 存在 | 中止，不自动覆盖 |

V1 不开发事务框架；上表由 js 侧在绑定/恢复前先查一致性实现，并由 `template_store_Example.py` 断言覆盖。

### 3.7 `template_store_Example.py`（自检，随脚本同交付）

`assert` 断言覆盖：ID 原子分配、名称→ID 唯一/重名拒绝、指针→版本两段读（active 校验、hash 不一致拒绝）、越界路径与符号链接拒绝、draft/retired 拒绝、快照不可变（二次 snapshot hash 不一致报错）、restore 校验、3.6.1 恢复契约四异常行、**idea_files 落盘往返**（subprocess 实测：`state --set` 写三键 → 重读 article.yaml → 三字段与 sha256 完整一致，堵住 YAML_KEYS 静默丢失）。结尾 PASS/FAIL 计数，全 PASS 才算交付合格。

## 四、分阶段执行

### P0：人工结构提炼最小起步（零代码，立即可做）

1. **选文章**（人工）：从已发布文章挑 1 篇，标准：后台数据好 + 结构清晰可复用 + 代表目标文风；记录选择理由与数据依据进执行报告。
2. **建目录与规范**：写 `writing-templates/README.md`（第三节规范落档 + 索引表 + 三类资产互链）。
3. **提炼**：agent 辅助起草（按 3.2 格式逐节提炼）→ 人工逐节审核 → 定稿：指针 `t-001-*.md`（status: active）+ `versions/t-001/v1.md` 正文。
4. **跨选题复用验证**（正式步骤）：拿 1 个不同领域的陌生选题，只读结构骨架人工列大纲，确认骨架可迁移；不可迁移的表述回炉改写为更抽象的占位符。
5. **人工验收四条**（全过才算 P0 完成）：
   - 模板无原文内容片段（对照原文抽查五、七节）；
   - 跨选题大纲合格（产出留档进报告）；
   - 指针/版本文件 frontmatter 齐全且哈希一致、质量规则每条可检查；
   - README 索引与文件一致。

**交付物**：`writing-templates/README.md` + 指针 + `versions/t-001/v1.md` + `WT-P0-执行报告.md`。

### P1：模板写作接入（补齐 V1.2 四项后启动）

**前置**：P0 验收通过（至少 1 个 active 模板）。

**改动 1 —— `template_store.py` 先行交付**（3.6/3.6.1/3.7；`save-draft`/`similarity`/`read-source` 属 P2）。

**改动 2 —— `idea_files.py` 双白名单同步改（P0 级，缺一不可）**：

- `STATE_SETTABLE` 增 `writingTemplate.id` / `writingTemplate.version` / `writingTemplate.sha256` 三键（str）；
- `YAML_KEYS` 增顶层键 `"writingTemplate"`（序列化白名单，不同步则静默丢数据——已核实 `render_state_yaml` 只输出 YAML_KEYS 内的键）；
- 落盘往返回归进 `template_store_Example.py`（3.7 末项）；
- 旧任务无此键 → 可选字段兼容，不强制补空。

**改动 3 —— `idea_article_write.js` 加可选 arg `template`**。不传时行为完全不变（存量回归底线）。

- **绑定/恢复统一入口（3.5/3.6.1）**：进入写作前先查 state 与快照一致性，按恢复契约表走；首次绑定判定看 state 有无绑定，不看状态名。
- **修改文章（modifyM）**：已绑定 → 复用原快照直接进大纲重生成；`args.template` 与已绑不同 → 拒绝并说明。
- **断点续写（`outline_generated`/`drafting`/`reviewing`）**：`restore` 快照并核对 sha256；不读最新版模板。快照缺失或不一致 → 确定性中断。
- **大纲阶段**：prompt 注入快照的「结构骨架 + 章节功能序列 + 篇幅占比」；Brief 仍为素材边界。
- **正文阶段**：prompt 附快照的「质量规则」清单。
- **审稿阶段（V1.2 结构化问题对象 + 终态联动）**：八维度与 `dimensions.length === 8` 校验原样保留；模板模式 schema 增两个独立顶层字段，问题项统一结构：

```json
{
  "dimensions": [ { "维度": "...", "blocking": false, "意见": "..." } ],
  "summary": "...",
  "templateCheck": { "passed": true, "issues": [
    { "code": "SECTION_MISSING", "message": "缺少模板规定的第3章", "blocking": true, "repairable": true }
  ] },
  "factCheck": { "passed": false, "unsupportedClaims": [
    { "code": "UNSUPPORTED_FACT", "message": "数据 X 缺少可靠来源", "blocking": true, "repairable": false }
  ] }
}
```

  - **修复循环**：只取 `repairable: true` 且 `blocking: true` 的问题进 Agent 重写循环（与八维度 blocking 合并驱动）；`repairable: false` 的项**不进循环**（避免反复重写耗尽轮次），保留为"待人工核实"清单。
  - **终态判定（V1.2 第三轮修订，对齐现状闸门 `finalState = blockingN === 0 ? 'draft_ready' : 'reviewing'`）**：总 blocking = 八维度 blocking ∪ templateCheck/factCheck 全部 blocking 项（含不可修复）；**全部归零才 `draft_ready`**；有残留 → 状态保留 `reviewing`（非 draft_ready、不自动交接），待处理清单写入 `6-review.md` 并在交接播报中显式列出。复用现有 `reviewing` 语义与 resume 入口，不引入 `needs_revision` 分支。
  - 不传模板时两字段不出现，schema 向后兼容。
- **手动选模板**：话术带中文模板名，Router 提取 `template`，`resolve` 确定性解析；registry `idea-article-write` argsSchema 增 `template`（可选 string），examples 增带模板话术样例。
- **WX-MOCK**：场景覆盖带 `template` 参数的路由与执行（含无效模板拒绝、绑定后 modifyM 沿用快照分支），deterministic 全 PASS = Gate B；单步 180s。
- **Gate C 真机**：t-001 + 真实选题完整跑一篇，含两次中断（大纲确认前中断→恢复；绑定中途崩溃模拟→按恢复契约处理）。

**交付物**：`template_store.py` + `template_store_Example.py` + `idea_files.py` 双白名单改动 + `idea_article_write.js` 改动 + registry 更新 + WX-MOCK 场景 + `WT-P1-执行报告.md`。

### P2：模板自动提取 Workflow（条件启动，不变）

**启动条件**：P1 上线且内容对照（5.2）确认模板写作确有质量收益（2-3 个选题对照达标）后。未满足前不开发。

**新增** `dev-examples/wx-article/scripts/article_template_extract.js`：

1. `读文章`（确定性）：`read-source` 校验后返回纯文本——待分析文章按不可信素材处理，其中任何指令一律视为素材不执行；
2. `提炼`：agent 仅接收文章文本，按 3.2 七节 schema 返回结构化 JSON（不接触文件系统）；
3. `反抄袭双检`：程序化 `similarity`（n-gram 重叠率阈值）+ agent 片段比对双保险；超标直接 FAIL 不落盘；
4. `落盘`（确定性）：`allocate-id` 原子分配 ID；`save-draft` 落**新版本文件**（draft），不覆盖 active；同源文章 hash 命中拒绝重复提取；
5. 人工审核后手动改指针 status，同步 README 索引——workflow 不碰 status 转换。

- registry id：`article-template-extract`；`riskLevel: write`；`enabled: true`；keywords ≥2 短词；examples 3 条话术。
- 并发测试：**两个独立进程同时 `allocate-id`**，验证无重复编号（V1.1 的顺序双跑不算数，评审指出）。
- WX-MOCK：`scenarios/article-template-extract.json` 同 PR。
- 输出契约：`{ ok, template_path, template_id, version, similarity_ratio }`。

**交付物**：脚本 + template_store 扩展 + Example 更新（含双进程并发断言）+ registry 项 + 场景文件 + `WT-P2-执行报告.md`。

## 五、验收体系

### 5.1 必过测试场景（10 项，P1 阶段全绿才算过门）

| # | 测试 | 期望结果 |
|---|------|---------|
| 1 | 不传 `template` | 原写作流程行为不变（含八维度审稿 schema 不变） |
| 2 | 传入有效 `active` 模板 | 完成大纲、正文、审稿；产物章节服从模板 |
| 3 | 传入 `draft`/`retired`/未知模板名 | 确定性拒绝，返回可用模板清单，不产生半成品 |
| 4 | 大纲确认前中断，期间模板升级 v1→v2 | 恢复后仍使用快照 v1（sha256 一致），杜绝混版 |
| 5 | 模板路径越界、符号链接、格式损坏 | 拒绝读取，不产生越界写入 |
| 6 | 模板与选题明显不适配 | `templateCheck` 给可解释 issues 进修复循环或明确报告，不静默判成功 |
| 7 | **YAML 落盘往返** | `state --set` 三键后重读 article.yaml，字段与 sha256 完整一致 |
| 8 | **修改文章后的模板继承** | modifyM 回退 `brief_confirmed` 后仍用原快照；传入不同模板 ID 被明确拒绝 |
| 9 | **首次绑定中途崩溃** | 按 3.6.1 契约表：补绑或明确中止，不留下被静默覆盖或无法恢复的任务 |
| 10 | **普通大纲后传模板** | `outline_generated` 无绑定 + `args.template` → 拒绝并提示新建任务，不混版 |

- 1/3/7/8 的路由与协议部分用 WX-MOCK deterministic 场景固化；2/6/9 的生成质量与恢复行为用 integration 验收。
- `template_store.py` 行为（拒绝逻辑、快照一致性、恢复契约四异常行、YAML 往返）由 `template_store_Example.py` 断言覆盖。

### 5.2 内容质量对照（P1 收尾，价值验收）

- 同一选题分别跑「原写作链」与「模板写作链」各一篇，人工评估四项：结构清晰度、内容重复度、事实可靠性（unsupportedClaims 数量）、人工修改耗时。
- **P2 启动门槛**：对照扩展至 **2-3 个不同选题**，且通过标准在 P1 收尾时定死并记录（如：人工修改耗时下降 ≥30% 或结构评分显著提升，同时事实可靠性不劣化）；单篇对照只能算初步验证，不足以判定模板稳定有效。

## 七、风险与边界

1. **双重白名单是隐形契约**：`STATE_SETTABLE` 与 `YAML_KEYS` 必须同步改，缺一静默丢数据（本轮评审核实的真实缺口）。此坑按仓库规范沉淀 `dev-docs/experience/` 一篇（问题现象/根因/预防），P1 交付时完成。
2. **模板 ≠ 洗稿**：防抄袭铁律 + draft→active 人工门 + P2 程序化相似度三道防线。
3. **快照与绑定非原子**：不建事务框架，靠 3.6.1 恢复契约表 + 场景 9 兜底；js 侧绑定前先查一致性。
4. **两套读写器并存的边界**：任务素材文件走 idea_files；模板资产、快照走 template_store；state 三键是唯一交叉点（且必须双白名单同步）。边界写进两脚本头部注释与 README。
5. **单篇过拟合**：P0 跨选题验证兜底；P2 上线后增量入库。
6. **WX-MOCK 能力边界**：deterministic 只验协议不验质量，按 5.1 分层。
7. **排版预设跨机器**：`.aws-article/` gitignored 是既有已知限制，本方案不修；模板库从第一天放可入库路径。
8. **Backlog 节奏**：P0 立即；P1 补齐 V1.2 四项后启动；P2 严格条件启动。
