## 一、需求 A：Workflow 失败任务统计与自动诊断（日报 5.2）

**优先级：高（日报原话："建议优先级：高于继续增加外围功能"）。**

**背景**：日常微信 Bot 测试失败多，任务成功率主观估计约 50%，无每日准确统计，缺真实分母。

**目标能力：**

1. 统一记录微信任务全阶段结果：消息 → 路由 → 审批 → Run 启动 → 业务交付。
2. 每天定时生成质量统计：有效任务数、已确认成功/失败、待确认/拒绝/中断/unknown、任务层与 Run 层成功率。
3. 自动扫描失败记录，读取 Manifest、Journal、运行错误、必要日志；脱敏并限制诊断访问权限。
4. 按错误指纹归并重复问题，输出：发生次数、影响范围、证据、可能根因、修复建议、置信度。
5. 后续（非首版）：生成隔离分支修复补丁与 WX-MOCK 回归用例，测试 + 人工审核后合并。

**安全边界：**
- 首版只读分析 + 修复建议；不自动改线上代码。
- 不自动重放公众号发布或可能重复扣费/写入的任务；`unknown` 状态需人工核对实际副作用。

**关联**：明日计划 P0"建立任务成功率最小统计基线"即本需求的最小落地版（先手动/脚本汇总一天任务结果，区分 task 与 run 状态）。

## 二、需求 B：优质文章写作模板库（日报 5.1）

**优先级：Backlog（初期手动，不急建平台）。**

目标：把优质历史文章转为可复用写作结构，不是复制原文。

1. **模板提取 Workflow**：输入优质文章，提炼章节功能、叙事逻辑、语气、案例用法、质量规则，输出带来源和版本的 Markdown 模板。
2. **模板写作 Workflow**：输入选题、素材和指定模板，生成新文章并做事实审稿。
3. **三类资产区分**：写作模板（怎么讲）/ 排版模板（怎么展示）/ 视觉生图模板（图片怎么设计）。
4. 初期手动选模板；自动推荐与效果 A/B 对比属后续。

**最小起步**（明日计划 Backlog）：先选 1 篇高质量历史文章做人工结构提炼。

## 三、生图链路遗留需求（日报 2.2 卡点 + 优化设想）

**现状卡点（真实使用发现）：**
1. 生成结果未严格遵循风格/版式/提示词模板。
2. 要求带文字的图片，实际生成缺文字。
3. 一批图片需求频繁开关/切换 Chrome 页面，耗时且不稳定。

**待实现优化：**
- **浏览器会话复用验证**（明日 P1）：先确认 `image-use`/浏览器调用能否同一会话、同一窗口和标签页顺序完成整批图片，不假定一定能复用页面；再决定是否改造队列执行器。
- **图片证据链**：每张图绑定独立 ID、输入 prompt、输出文件、执行结果、失败原因、生成证据。
- **单窗口串行批处理**：完成一张再下一张，失败按状态安全恢复，避免重复计费/重复提交。
- **文字验收**：对"必须带指定文字"场景增加文字内容验收；必要时评估"无字底图 + 确定性排版叠字"方案。
- **批量质量度量**：统计总耗时、成功率、人工介入次数、模板符合率，不只检查文件存在。
- **生图质量专项排查**（明日 P0）：抽 3 张实际样例，对照编译后 prompt 检查"模板偏离"与"文字缺失"。
