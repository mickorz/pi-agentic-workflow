# 微信调度系统 P3 — 扩展预留（M3，V1 外）

> 版本：V1.0 / 方向登记，不排期、不设 Gate
> 需求依据：《需求》§1.3 非目标、各组 P2 条目

V1 交付后的候选方向。每项启动前需先回补需求评审（作为 V2 需求增量），不在本执行文档族内展开：

| 方向 | 需求锚点 | 备注 |
|---|---|---|
| 附件/语音/图片输入 | §1.3 | 统一消息格式已预留扩展字段 |
| 多用户/多微信账号 | §1.3、D-07 | 现有单用户绑定模型的推广；配额体系需单独立项 |
| 多 IM 通道（BotAdapter 插件化） | WG-008 | 契约已隔离，验收即"新通道零业务逻辑改动" |
| 检索升级（BM25/向量） | IR-010 | 样例集与评估脚本可复用 |
| Workflow 热更新与版本治理 | WR-005/006 | 哈希/Resume 语义已定，重点是注册表版本化 |
| 可视化管理（复用 V2 Web） | §1.3 | 与主项目 V2-P1/P2 汇合 |
| 成本/质量基线分析 | MR-011、§11.3 | 基线数据积累后评估 Bifrost 实际收益 |

约束提醒：任何 P3 方向都不得突破《需求》§1.3 中"不自动生成任意 Workflow"与"不公开 SaaS"的红线，除非另行立项重审。
