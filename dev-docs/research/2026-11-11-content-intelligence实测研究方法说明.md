# Content Intelligence 首次实测（T6）研究方法说明

> 日期：2026-11-11
> 对象：选题「企业沉睡的数据，如何变成 AI 生产力」研究过程（报告见 `content-intelligence/research/2026-11-11-企业沉睡数据AI生产力.md`，样本 23 条见 `content-intelligence/samples/enterprise-ai/`）
> 用途：回答「用了哪些渠道、怎么分析的」，并沉淀可复用的渠道实测结论；后续每次研究可参照本说明执行，渠道清单随实测更新。

## 一、分析渠道

渠道分两层：**工具层**（用什么抓）和**平台层**（抓哪里）。证据等级（A/B/C）由两层共同决定。

### 1.1 工具层（会话内可用，零新增依赖）

| 工具 | 用途 | 本次实测结果 |
|---|---|---|
| `web_search_prime` | 搜索 + 正文摘要（中英文均可） | **主力**。4 轮搜索全部成功，摘要质量足以支撑 C 级登记与候选筛选 |
| `web_reader` | 抓原文全文（判定 A/B 级的依据） | 成功率 6/10 左右：知乎/CSDN/woshipm/独立博客可完整抓取；InfoQ（SPA 只返回壳）、Reddit（反爬拦截）、Medium（超时）、tmtpost（超时）、B站（JS 渲染只回标题）失败 |
| `web_fetch` | 备用抓取（带提问提取） | InfoQ 二次尝试仍空；作为 web_reader 失败后的复核手段 |
| `web_search`（DuckDuckGo） | 英文搜索 | 本次 3 次调用全部超时中止，实际未产出；英文搜索由 web_search_prime 覆盖 |

### 1.2 平台层（本次实测的 12 类渠道与可得证据等级）

| 渠道 | 命中量 | 可得证据等级 | 实测说明 |
|---|---|---|---|
| CSDN | 5 | **A**（正文全 + 浏览数在页面元数据中） | 中文技术教程主阵地；点赞/评论多数不展示，浏览数仅部分文章在 description 暴露 |
| 知乎（专栏/回答） | 4 | **B**（正文全；互动数据不可靠） | 正文完整可抓；专栏页无赞同/阅读数，回答页元数据里的赞数无法确定归属——只能标 B 或未采集 |
| 人人都是产品经理 | 1 | **B**（正文全，无互动数） | 业务/产品视角内容的主要中文来源 |
| 厂商博客（Splunk/Atolio/Intelliarts/Confluent/BetterYeah） | 5 | C~normal | 同质化 SEO 综述，天然是普通对照组 |
| 英文独立博客 | 1 | **B**（正文全，无计数器） | 工程深度最高的一档（如 1200+ 小时实测文） |
| Medium | 1 | C | 超时未取全文，付费墙风险 |
| InfoQ | 1 | C | SPA 渲染反爬，两次工具均失败；摘要靠搜索结果 |
| 钛媒体 | 1 | C | 抓取超时 |
| Reddit | 1 | C | 明确反爬拦截（blocked by network security），不要重试硬爬 |
| B站 | 1 | C | 页面 JS 渲染，播放数未捕获；仅标题可用 |
| AWS 中文博客 | 1 | C | 布道文，痛点词汇表来源 |
| 聚合/转载站（shaqiu 等） | 1 | C | 清单转载，需回溯原始出处 |

**渠道结论**：当前工具面下，**A 级（全文+指标双全）实际只有 CSDN 部分文章和少数元数据齐全的页面能拿到**；知乎/woshipm 只能到 B；公众号生态、Reddit、InfoQ 正文不可得。这直接解释了本次研究「A 级仅 2/23、爆款确认 0」的元发现。

## 二、怎么分析的（五步）

### 步 1：候选池构建（关键词组合 × 渠道分流）

关键词按三段组合：**选题词**（企业知识库 RAG 落地 / enterprise RAG lessons learned）× **平台词**（知乎/博客/教程）× **表现词**（避坑/踩坑/高赞/失败原因）。4 轮搜索（中文 2 + 英文 1 + B站专项 1）得到约 25 条候选。

### 步 2：分层精读（不平均用力）

按「与本选题的相关度 × 拿到 A 级证据的潜力」排序，只对头部候选做全文精读（web_reader），其余停留在搜索摘要级：

- 全文精读 6 条 → A/B 级样本（woshipm 失败分析、CSDN 避坑指南、英文 1200 小时文、知乎红杉回答、知乎 RAG 构建、知乎生产力悖论）
- 摘要级 17 条 → C 级样本（含全部抓取失败的渠道）

抓取失败不硬爬（Reddit 拦截即放弃），失败记录如实写进样本的 evidence 字段。

### 步 3：逐条登记（YAML 模板 + 三条硬纪律）

每条样本按 `templates.md` 模板登记，纪律执行点：

- **指标三值**：CSDN 避坑指南浏览 304（页面 description 暴露，真实数字注采集日期）；知乎回答赞数因元数据归属不明标「未采集（附原因）」；厂商博客无计数器标 `N/A 平台不公开`
- **证据分级**：全文读到才算 full_content_read: true；只读摘要一律 C 级
- **tier 判定**：304 浏览虽【分析判断】明显偏低，但样本内无同平台对照组 → tier 判 `unknown` 而非凭直觉标「普通」；厂商 SEO 文凭内容定位标 normal 且注明「置信度低」

### 步 4：交叉统计（手工聚合，无脚本）

四个维度交叉：

1. **八类分布** → 供给结构：实操教程 11/23 = 技术教程供给饱和
2. **证据分布** → 结论强度边界：A 2/B 4/C 17 → 触发报告第 8 段可信度声明
3. **tier 分布** → 指标可得性：unknown 17 → 「爆款 0」元发现
4. **平台 × 格式** → 渠道偏斜：中文 17/英文 6，long_article+tutorial 占 19/23

### 步 5：差异化推演（从统计到结论）

三步推演，每步结论标注 D9 等级：

1. **饱和度分析**：哪类内容条数多 → 该题材供给饱和（教程型 11 条 → 靠结构无法差异化，【观察事实】）
2. **真空带识别**：A/B 级样本中**缺失**的内容形态 → 双视角成文 0、第一手案例 0、成本数据仅 1 条二手 → 差异化机会（【分析判断】）
3. **普通样本归因**：6 条 normal 组的共同特征（无物件/无立场/无代价）→ 反推「普通为什么普通」三差异点（【分析判断】），爆款验证缺位部分降级【待验证假设】

## 三、本次实测的局限（如实）

1. 公众号生态内容完全缺席——最该研究的同渠道样本不可得，属结构性盲区，只能靠 P2 自己的发布数据补
2. DuckDuckGo 工具本次不可用，英文渠道覆盖靠 web_search_prime 单点
3. 精读 6 条/摘要 17 条的分层策略意味着六维拆解的深度对 C 级样本只到标题与摘要层
4. 统计为手工聚合，样本量再扩大时建议写校验脚本（Python 标准库即可），当前量级暂无必要

## 四、可复用清单（下次研究直接照抄）

- 渠道优先级：CSDN/知乎/woshipm/英文独立博客（可达正文）→ 厂商博客（对照组）→ InfoQ/Reddit/Medium/B站（默认 C 级预期，失败不硬爬）
- 关键词三段式：选题词 × 平台词 × 表现词
- 精读配比：候选池 ~25 条 → 全文精读 6~8 条 → 其余摘要级登记
- 每轮搜索后立即登记样本（避免集中补录时丢失上下文）
- 报告必带：证据分布统计 + 可信度声明 + 搜索盲区声明
