# T1 会话复用四维验证报告——keep-tab 收益不成立，T2 缓行

> 日期：2026-10-28
> 任务：《生图链路遗留需求执行方案》V2 · T1（阶段一验证任务）
> 环境：本机 Chrome（chrome-use relay）+ ChatGPT 订阅 web 后端 + image-use v0.34.5（pin 7f97846）
> 方法：同 prompt 测试图（小机器人主题，带 no text 约束），基线组（默认参数）3 张 vs 实验组（`--keep-tab`）3 张，全部真实生成，记录 stderr 全时间线。

## 一、四维结论总表

| 维度 | 基线（默认） | 实验组（--keep-tab） | 结论 |
|---|---|---|---|
| 1 标签页行为 | 每张走 `opening ChatGPT via current Chrome`（5.0-6.2s 接管）；生成后关 tab | 同样每次走 `opening ChatGPT`（3.7-6.4s 接管）；**结束后 tab 保留** | 前段接管耗时两组无显著差异；keep-tab 只改结束行为 |
| 2 对话上下文 | 每张新建对话，生成后删对话记录 | **同样每张新建对话**；仅保留历史记录不删 | **实测确认：对话上下文不复用**（评审 P0-1 断言证实） |
| 3 单图耗时 | 61s / 104s / 63s（均值 76s） | 51s / 60s / 59s（均值 57s） | 差异主因是基线第 2 张**生成阶段**离群慢（104s），非流程性提速；结构性收益仅省"删会话"步骤约 1-2s/张；**3+3 样本不足以断言可量化缩短** |
| 4 稳定性 | 1/3 出现删会话失败（CDP relay timeout 8s → 会话意外残留在账号历史） | 0/3 失败，行为确定 | keep-tab 少一个可失败步骤 |

## 二、关键证据（stderr 时间线）

1. **每次调用完整流程相同**：`relay connected → opening ChatGPT via current Chrome → using project 'imagegen' →（模型选择）→ generating → receiving → downloading → saved`。keep 组无任何"复用已有对话"痕迹。
2. **基线默认行为证实**：`conversation deleted (no history kept)`（每张生成后）。
3. **基线稳定性缺陷实锤**：第 3 张 `could not delete conversation (CDP error: relay timeout after 8000ms); it stays in history`——默认模式下删会话依赖 CDP eval，偶发超时后**会话残留**（与 keep-tab 的主动保留同效但不可控）。
4. 两组共有噪音（不影响判定）：`warning: model picker not found; leaving model as-is`（每张 1 次）、版本升级提示。

## 三、T2 判定：缓行（不做适配器改造）

按方案判据"批次耗时可量化缩短且失败不增"：

- **可量化缩短：不成立**。均值差 19s 由离群值驱动，不可归因于 keep-tab；确定性收益仅省删会话 1-2s/张。
- **失败不增：成立**，且少一个可失败步骤（删会话 CDP 超时）。
- **日报卡点 3 的真根因不在 keep-tab 能解决的范围内**："频繁开关 Chrome 页面"的体感来源是上游每次调用的 `opening ChatGPT` 固有动作（session 接管/导航），keep-tab 不改变它。

**结论：T2 不实施**。理由与保留路径：

1. 收益（1-2s/张 + 稳定性微增）撑不起改造与回归成本；
2. 若上游未来支持"同一对话顺序连发"（真正的上下文复用，可显著省去每张 5-15s 的接管+建会话开销），届时重新评估——那才是结构性提速；
3. V2 方案的 env 开关设计（`IMAGE_USE_KEEP_TAB=1` → buildArgs 追加 flag）保留为 5 分钟级预备改造，已写清清理策略，需要时可随时落地。

## 四、对既有经验的修正

1. V2 方案卡点 3 根因表："可能是默认删会话/关 tab 语义下的重复打开"——**部分证实**：删会话确是每张固定开销且偶发失败，但它不是耗时的主要构成（1-2s vs 单图 60s+）。
2. "上游固定 chatgpt-web session 共享单 tab"的机制表述需修正为：**共享的是 chrome-use 接管通道/daemon，不是 ChatGPT 对话页面本身**；页面级每次仍是 opening 动作。
