## 3. 结论

1. **无签名直连只有短暂容忍窗口**：首次成功后约 10 分钟内，同 IP + 同 Cookie 的无签名请求被收紧为 200 空 body。这是动态风控，不可依赖。
2. **undici TLS 指纹被识别**：同一时刻 curl 有数据、Node fetch 空 body，说明抖音按 TLS/HTTP 指码差异化对待，因此 `fetchDouyinOneVideo` 固定走 curl 子进程（`VD_CURL` 可覆盖路径）。
3. **签名算法本身正确**：@moonr/abogus 生成的 a_bogus 与 DDA abogus.py 生成的结构一致（前缀同模式）；DDA 原版同样被拦，证明被拦的是本机环境（IP + 公开 Cookie 组合已被标记），不是签名实现问题。
4. **公开 Cookie 的定位**：DDA 内置公开 Cookie 适用于"低频 + 随缘"；持续稳定使用需要登录 Cookie（vcli 的 cdp-cli 导出机制已支持抖音，digest 流程会自动导出）。

## 5. 对阶段一计划的影响

- T0 结论从"组合 A（跳过签名）成立"修正为"组合 B（必须签名）"；douyin.ts 已按组合 B 实现并保留组合 A 作为回退路径（签名失败时的错误信息会提示）。
- Cookie 优先级按计划实现：参数传入（cdp-cli 导出）> 内置公开 Cookie。
- digest 集成（T4）的降级策略不变：hybrid 解析失败仅 warn，不影响 yt-dlp 主流程。
