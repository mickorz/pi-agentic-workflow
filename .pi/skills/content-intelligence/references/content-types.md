# 八类内容类型定义（content-types）

> 用途：样本分类与内容策略选择的判断规范。每类五段：定义与示例题 / 识别特征 / 适用选题与读者 / 真实性要求 / 反面模式。
> 分类规则：每条样本标一个主类型，允许一个副类型（复合），报告写「主+副」，如「真人故事型+实操教程型」。

## 1. 数字盘点型

- **定义与示例题**：以数字+清单组织内容。示例：2026 年值得关注的 7 个 AI Agent 工具。
- **识别特征**：标题含具体数字与复数名词（N 个工具/方法/坑）；结构为并列清单，每项独立成段。
- **适用选题与读者**：工具选型、行业盘点、方法论汇总；读者需要「一次看全」的收藏型阅读。
- **真实性要求**：清单内容真实有价值——每项都必须独立成立，不能为凑数字收录注水项；数量承诺与实际条数一致。
- **反面模式**：数字攀比（7 个不够硬凑 10 个）；清单项之间无区分度；只列名不给判断。

## 2. 高能冲击型

- **定义与示例题**：反常识、冲突、趋势变化的判断型内容。示例：未来的软件公司，可能不再招前端和后端了。
- **识别特征**：标题直接抛反常识断言（不/不再/正在死/被取代）；结构为断言→证据→推理→结论。
- **适用选题与读者**：趋势判断、行业变化；读者需要「提前知道别人还不知道的事」。
- **真实性要求**：反常识观点必须有现实证据支撑，逐条核对哪些有真实证据、哪些只是标题党；证据链断裂就降级为待验证假设。
- **反面模式**：在公众号滥用短视频式夸张标题（断言无证据、惊悚无下文）；观点与证据脱节；为冲击而冲击、自己都不信。

## 3. 点名观众型

- **定义与示例题**：身份代入、精准受众的内容。示例：如果你是企业技术负责人，这 5 个 AI 能力必须了解。
- **识别特征**：标题含明确身份词（如果你是…/做…的人）；结构按该身份的具体处境组织。
- **适用选题与读者**：面向特定角色的建议（老板/技术负责人/程序员/独立开发者）；读者要「说的就是我」。
- **真实性要求**：点名的身份处境必须真实——描述的痛点是该身份真实会遇到的，不是想象的标签。
- **反面模式**：身份词只是标题诱饵，正文内容与身份无关；点名过泛（所有人都能代入=没人代入）。

## 4. 对比测评型

- **定义与示例题**：对立、差异、决策帮助的内容。示例：OpenCode 和 Claude Code，企业开发应该怎么选？
- **识别特征**：标题含 A vs B / 怎么选；结构为维度表或逐维度对比，结论指向决策建议。
- **适用选题与读者**：同类工具/方案选型；读者正处于决策关口，需要「帮我做决定」。
- **真实性要求**：必须有真实的比较维度和亲测/可查证依据；不能只搬参数表，每个维度要说明差异对谁有影响。
- **反面模式**：伪对比（一方是稻草人）；维度不平行（拿 A 的强项比 B 的弱项）；结论骑墙不给建议。

## 5. 需求场景型

- **定义与示例题**：痛点、解决方案、落地价值的内容。示例：企业有大量历史文档，怎样让 AI 真正用起来？
- **识别特征**：标题描述具体场景+难题（怎样/如何 + 场景痛点）；结构为痛点→方案→落地路径→效果/成本。
- **适用选题与读者**：企业落地、工作流改造；读者（老板/AI 负责人）正被同类问题困扰。
- **真实性要求**：痛点必须真实存在且常见；方案要有落地依据（案例、成本、周期），不画饼。
- **反面模式**：场景泛化到没有读者（什么行业都能套=没有行业成立）；方案环节缺失细节，只讲理念不讲怎么做。

## 6. 真人故事型

- **定义与示例题**：人物、过程、结果、经验的叙事内容。示例：一个程序员，如何用 AI 一个人完成过去一个团队的工作？
- **识别特征**：标题含具体人物/第一人称；结构为处境→转折→过程→结果→经验。
- **适用选题与读者**：亲历复盘、转型故事；读者通过别人的真实经历获得参照。
- **真实性要求**：**真实人物和真实经历，禁止编造案例**——人物、时间线、结果必须可核对（最好是作者自己或注明来源的公开案例）。
- **反面模式**：虚构「一个朋友」式伪案例；结果夸大到不可信；故事与读者处境无关联点。

## 7. 实操教程型

- **定义与示例题**：步骤、代码、可复现、实用性的内容。示例：从零搭建一个可以自动执行任务的 Agent。
- **识别特征**：标题含从零/搭建/上手/步骤；结构为前置条件→分步骤→踩坑点→验证结果。
- **适用选题与读者**：动手场景；读者要「照着做能跑通」。
- **真实性要求**：**必须有实际操作和验证结果**——每个步骤都应该是作者真实跑过的，代码/配置可复现；跑不通的部分如实标注。
- **反面模式**：步骤跳步（读者照做必卡）；只写快乐路径不写报错处理；没验证就发布。

## 8. 观点分析型

- **定义与示例题**：独立判断、专业认知、观点差异的内容。示例：AI Agent 普及之后，程序员真正需要提升的是什么？
- **识别特征**：标题提真问题（什么才是/真正/本质）；结构为观点→论据→与其他观点的交锋→自己的判断。
- **适用选题与读者**：认知升级、专业判断；读者要「一个值得参考的独立判断」。
- **真实性要求**：**必须有作者自己的判断**，不是汇总别人观点；引用他人观点时明确区分「谁说的」和「我怎么想」。
- **反面模式**：观点拼盘（A 说 B 说 C 说，唯独没有我说）；判断没有论据，只有姿态；回避争议和稀泥。

## 分类判断速查（给分类时用）

一条样本怎么快速定类？按优先级问：

1. 标题有数字+清单 → 数字盘点型；标题 A vs B → 对比测评型；标题点名身份 → 点名观众型
2. 都不满足时看结构主张：讲一个反常识断言 → 高能冲击型；讲一个具体场景难题 → 需求场景型；讲一个人的经历 → 真人故事型；讲怎么做 → 实操教程型；讲一个判断 → 观点分析型
3. 仍难定 → 看正文主结构（并列=盘点、递进=观点/冲击、叙事=故事、分步=教程），主类型取主导结构，副类型取次要结构

## 与表现分层的关系（防混淆）

- 内容类型（本文件）回答「这是什么策略的内容」——与好坏无关
- 表现分层（tier，见 templates.md）回答「它在同平台同主题里表现如何」——必须有数据依据
- **严禁**把「我觉得这篇写得好」当 tier 判定依据，也**严禁**把爆款类型占比当因果（某类爆款多 ≠ 该类更容易爆，那是 D9 待验证假设）
